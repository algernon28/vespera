# The private-paths guard

What AGENTS.md says in short, and what an agent needs when a command is refused: what the hook enforces, the commands it admits, the `.claude` folders no agent writes into, and how the hook is held. AGENTS.md keeps the rules and the habits that spare a refusal; the rest is here.

## The operator's documents are never read by an agent

**No agent reads a document in an archive, walked or not, or in a seed set, and none writes there** (ADR-264). The archives can hold sensitive documents, and a document is read only by the local models Vespera runs (Docling, and the models Ollama serves). This holds for every agent and subagent, whatever its task, including a run it is driving: labels, floors and approvals are the operator's, or a local model's ([#423](https://github.com/algernon28/vespera/issues/423)), never an agent's. The hook keeps no list of archives, so it takes every path outside the allow list for one that may lie in an archive. **A working directory is open as the place it lies in**: under an allowed root every file in it, `vespera.db`, `logs/vespera.log` and the pages that carry text of documents included, is open to every tool, but for the deliverable tree drawn in it, and outside the allow list it stays outside. What an agent reads there stays in the conversation, and what it may write there is in AGENTS.md.

`.claude/hooks/private-paths-guard.mjs` enforces it for eight tools: Read, Grep, Glob, Edit, Write, NotebookEdit, Bash and PowerShell. It refuses a call that names a path outside `.claude/allowed-paths.txt`, but for Glob, which prints names and is let through wherever it looks, and a shell command of listed programs (below). In a shell command it reads drive paths, relative paths and paths headed by a variable of the environment, and the command's current directory; a relative path is read against every folder the command names, so `cd` to a folder the hook reads does not get round it. On Windows it reads every path once more as Windows opens its names, each without a stream name after a colon and then without the dots and spaces that end it, so `wd.\report.html` is `wd\report.html`; and it refuses there a name made only of dots, spaces or a stream name, so a command whose text holds `a/.../b`, `./...` or a bare `...`, or a token that begins with a colon, as `'{"n":1}'` and `sed ':a'` hold one, is refused on Windows, and that text goes in a file; a quoted blank argument, as in `tr '\n' ' '`, is not. It is an allow list, so an archive on a new path is refused without being named. A refused path that is legitimate and holds no document goes in `.claude/allowed-paths.local.txt` (gitignored), by the operator. The hook does not see an `mcp__*` tool, Monitor, a path a script builds at run time, or a rooted POSIX path such as `/tmp/x` in a shell command; this rule covers those, and ADR-196 lists the others that are known, which is not all there are.

**A deliverable tree is read as outside the allow list wherever it lies** (ADR-283). No agent reads a file in a tree, the copies of the operator's documents, the pages and pictures written from them, the index, `documents.csv` and the marker, and none writes there, whether the tree is drawn in a working directory or at a named root, and an agent may list its names. The guard knows a tree by its marker: a folder that directly holds a name `vespera-deliverable.txt`, which every tree carries at its top (ADR-276 §3), is a tree's top, and every path at or beneath it that the allow list lets through is refused as a path outside the list is, so Glob and a listed command (below) are let through and nothing else. It asks for the marker from the path up to the last folder the list names, so a path outside the list still costs no lookup; any name there is a marker, and it is not read. The operator need not keep a deliverable root off `allowed-paths.local.txt`. The guard does not see a search, copy, move or removal that names a folder above a tree (Grep, `grep -r`, `cp -r`, `mv`, `rm -r`), a tree drawn before ADR-276, which carries no marker until its next drawing, or a tree whose top lies above every allowed root; the rule covers those. Until the operator installs `docs/agents/guard-draft/hooks/private-paths-guard.mjs`, the rule is all there is.

**A shell command that names a path outside the allow list** is let through only when every program it runs is listed (ADR-264 §3): `ls`, `dir`, `stat`, `Get-ChildItem`, `gci`, `Get-Item` or `Test-Path`, each a bare word; or, alone in its command, `java -jar <path>/vespera-<anything>.jar run`, with java bare or by a path, no option before `-jar`, and after `run` at most a root and `--db-dir=<path>`. The command is cut at `;`, `&&`, `||`, `|`, `&` and the line break, and each segment is checked: no assignment before a program, no `(`, `)`, backtick or `$(`, no `{` or `}` in PowerShell, and no redirect but `2>&1`, in Bash `>/dev/null` and `2>/dev/null`, and in PowerShell `>$null` and `2>$null`, each whole. So `ls <archive>` is let through and `ls <archive> | head`, `cat`, `cp`, `rm`, `find` and `du` of it are refused. The root is the one word of the jar the allow list does not decide, and is refused when it begins with `@`, holds `,`, `{` or `}`, or ends in the punctuation that ends a sentence, and so is a `--db-dir` value of that kind, or a word of the jar that shares a form with the root: its `--db-dir`, java, the jar and the current directory, where it writes its working directory, are checked as every path is. A listed command still meets the `.claude` rules below, a place named for reading only, a name that cannot be followed and the bounds.

**In practice** a shell command names a file by its absolute path and never by `..`, which the hook reads against a folder it may refuse; a script too long for one line is written with the Write tool and run by its path; a session's transcript is read with Read or Grep, whose path is checked as a path and not as a command's text.

ADR-196 is the record: what the hook must refuse, how it fails closed, and what it does not cover. ADR-201 amends it for links, and for four spellings it read wrongly. ADR-215 amends it for the `.claude` folders (below), ADR-217 for the names Windows opens as other names, and ADR-233 for what stands beside the name `.claude` in a token's text, a leading `~` in a file tool's field, and a link out of the guard's own `.claude` folder. ADR-261 and ADR-263 opened a few files of a working directory by name, and ADR-264 amends them all: it opens every working directory the allow list names, and outside the list refuses only what reads a file or writes. ADR-283 reads a deliverable tree as outside the allow list (above). ADR-212 admits one command that prints the database's counts, which stands beside the file tools; the hook admits exactly this command, and reads every other as before:

```
node .claude/hooks/working-directory-counts.mjs <working directory>
```

It is three words and nothing else: no pipe, redirect, second command, option, variable or `..`, the last two words bare or single-quoted, run from an allowed current directory. On Windows neither word begins with `/` or `\`, so name a drive path or a relative one. The script must be the one beside the guard, with the bytes the guard pins by SHA-256, so a change to the script is a change to the guard. It prints counts and sums keyed by walk id, run id and closed vocabularies, and how many files the working directory holds and their size: no path, no file or folder name but a run id's, and no text of the operator's. A count may be cited and compared; it is never a label, a floor or an approval, and a statement an agent writes is refused even when it returns only numbers.

**No agent writes into a `.claude` folder either** (ADR-215): not the home folder's, not this checkout's, not a worktree's. What is in one decides whether the hook runs and what it admits: `settings.json` and `settings.local.json`, `hooks/`, `allowed-paths.txt` and `allowed-paths.local.txt`, and the agent definitions, workflows and skills, each of which can register a hook or start a session. Three names stay an agent's to write beneath, in any `.claude` folder: `projects`, `plans` and `worktrees`. What that opens is `~/.claude/projects/`, which holds the memory directory and a session's transcript, `~/.claude/plans/`, and what lies beneath `.claude/worktrees/` outside each worktree's own `.claude`; a checkout's `.claude/projects/` and `.claude/plans/` are open too, and hold nothing a session obeys. `~/.claude/skills/` and `~/.claude/plugins/` are read and not written, with Read and Grep, and so is everything else in a checkout's `.claude`; Glob lists names in every `.claude` folder, as it does everywhere. A shell command is refused when any token of its text spells such a path, whatever heads the token, since its text does not say whether it writes: so stage with `git add -A`, and write a commit message that names one with `-F`. The counting command above is the one shell command that may name a path in `.claude/hooks`: the hook recognises it before it reads any path or text of it, and it is not admitted from a current directory that is itself a closed `.claude` folder. The counting script lies in that closed folder, so no agent edits it, which is what its pin wants. Nothing else under `~/.claude` is read with Read or Grep. A change to any of these files is written as a draft outside every `.claude` folder, held with `VESPERA_GUARD_DRAFT=<folder> node --test src/test/hooks/private-paths-guard.test.mjs` when it is the guard's, and put in place by the operator, who is handed the command. The hook does not see a path a command builds at run time or a program that writes these files without naming them, `git checkout` and `git apply` among them; this rule covers those, and ADR-215 §8 lists the others.

`src/test/hooks/private-paths-guard.test.mjs` holds the hook to the first nine records, `src/test/hooks/deliverable-tree-guard.test.mjs` holds it to ADR-283, against the draft in `docs/agents/guard-draft` while that is there, and `src/test/hooks/working-directory-counts.test.mjs` holds the script to ADR-212, against its draft in `docs/agents/guard-draft` while that is there, with no path of the operator's in any:

```
node --test src/test/hooks/private-paths-guard.test.mjs
node --test src/test/hooks/deliverable-tree-guard.test.mjs
node --test src/test/hooks/working-directory-counts.test.mjs
```
