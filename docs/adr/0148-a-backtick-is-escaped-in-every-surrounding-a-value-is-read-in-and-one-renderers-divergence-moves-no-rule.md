# ADR-148 — A backtick is escaped in every surrounding a value is read in, and one renderer's divergence moves no rule

- **Date**: 2026-09-25
- **Status**: accepted
- **Extends**: [ADR-138](0138-a-bracket-is-escaped-in-every-surrounding-a-value-is-read-in-and-the-link-text-stops-being-a-rule-of-its-own.md) — one character joins the escape set of the three Markdown text surroundings, on that record's own ground, and its closing paragraph on `marked` is answered here rather than amended. No sentence of any earlier record is found false by this one.
- **Rests on**: [`docs/research/deliverable-markdown-rendering.md`](../research/deliverable-markdown-rendering.md) **§10**, measured on 2026-09-25 across `markdown-it` 15.0.2 (both `html` settings), `marked` 18.0.13, the `commonmark` 0.31.2 reference (both `safe` settings) and GitHub's live `POST /markdown` in both modes — seven configurations, every fixture generated by running a writer and read back from the file it wrote. Also on §8b, where the lone backtick was found, and §9g, the other measured case of one renderer diverging. And on [ADR-137](0137-a-destinations-ampersand-is-percent-encoded-and-the-destination-is-a-fifth-surrounding.md) §4, the five surroundings and the rule that what a surrounding answers to decides the form of its rule; [ADR-138](0138-a-bracket-is-escaped-in-every-surrounding-a-value-is-read-in-and-the-link-text-stops-being-a-rule-of-its-own.md) §1 and §4, the precedent that a character structural in a surrounding is escaped there unconditionally; [ADR-136](0136-the-angle-bracket-and-the-ampersand-are-backslash-escaped-and-the-heading-becomes-a-fourth-surrounding.md) §3, the silent-deletion failure; and [ADR-134](0134-a-line-break-in-a-value-is-folded-and-three-escaping-rules-stand-because-there-are-three-surroundings.md), whose test — a value is escaped against the structure it actually lands in — this record applies.
- **Settles** [#261](https://github.com/algernon28/vespera/issues/261).

## Context

[#261](https://github.com/algernon28/vespera/issues/261) was opened on one measurement (§8b): a document whose name carries a single backtick is listed in a membership entry that `marked` does not make a link of — the whole entry prints as its own source — while the other six configurations form the link and resolve the `%60` the destination carries. CommonMark says a backtick with no partner is a literal backtick, so the six are right and `marked` is wrong, and the ticket asked two things: whether `Deliverable` should write a defensive escape against a renderer misreading a conforming document, and — the part that generalises — how much weight one renderer's divergence from the specification carries at all.

That question was asked of a case that turned out to be half of the finding. §10 drove the backtick through every position a value is read in, alone and in a pair, from the shipped writer, and the pair is not a `marked` finding:

- **Two backticks in one value form a code span in all seven configurations, in every Markdown text position** — both headings, both first-column cells, the third column, and the membership entry's text. Both backticks leave the rendered text and nothing marks where they were: GitHub labels the partition heading for `` seeds/a`b`c.docx `` as `Permalink: seeds/abc.docx` (§10c).
- **Two backticks around a character another rule escapes print that rule's backslash at the reader.** CommonMark processes no backslash escape inside a code span, so `` a`[x]`b ``, emitted as `` a`\[x\]`b ``, renders as `a<code>\[x\]</code>b` in every position, seven of seven outside link text and six of seven inside it (§10c). The reader is shown two backslashes the archive does not hold. The escapes ADR-134, ADR-136 and ADR-138 write are switched off by the one character none of them escapes.

Neither is exotic. NTFS permits a backtick in a name, a Docling title is arbitrary text off a title block, and a cluster title is what the generation model answered — and a model asked to name a group of documents about a piece of software is likely to put that software's name between backticks, because that is how it has seen such names written.

## Decision

### 1. `` ` `` is escaped as `` \` `` in a heading, in a cell and in a membership entry, unconditionally

A value written into an ATX heading (`inAHeading`), a table cell (`inACell`, and so the index's linked first column, which ADR-138 made a call to it) or a membership entry's text (`escapeLinkText`) has each backtick written as `` \` ``, on top of what those rules already write. `` \` `` is a CommonMark backslash escape — the backtick is ASCII punctuation — and measured (§10d), the escaped writer's output renders every backtick as a literal backtick, forms no code span, prints no backslash and forms every link, **in every position, for every value driven, in seven configurations of seven.**

The ground is ADR-134's test, and it is met the way ADR-138 met it for the bracket: the character **is** structural in these three surroundings under the specification, and measured so in all seven configurations. Nothing about that test needed `marked`.

**It is unconditional, for ADR-138 §4's reasons, and the reasons carry over without a word changed.** A rule that escaped a backtick only where a partner followed it would have to implement CommonMark's code span grammar — backtick runs matched by length, across whatever else the value holds — which is a second implementation of a grammar in a class whose rules guard grammars without implementing them; it would escape a value on one page and not on another by a predicate rather than by position; and it would buy nothing the unconditional rule does not, since `replace` leaves a value with no backtick untouched.

**The backslash is still escaped first**, for the reason every rule in this family gives: `` \` `` inserts the escape character, and a literal backslash already present must be escaped before it can merge with the one inserted after it. Where among the other replacements the backtick goes is free: none of `\<`, `\&`, `\[`, `\]` or `\|` contains a backtick, and `` \` `` contains no character another replacement acts on but the backslash, which has already run.

### 2. The CSV and the destination are untouched, and the destination's guard is load-bearing three times over

`quoted` gains nothing, for ADR-136 §5's reason: an RFC 4180 parser reads a backtick as data, and a backslash in a manifest column would reach a consumer as a character of the name. §10 read it back raw from both writers.

`relativeDestination` gains nothing either, and for the reason ADR-138 §6 gives for the bracket: `java.net.URI`'s path quoting already writes the backtick as `%60` (§8b), so it never reaches a destination raw. That encoding now guards the fifth surrounding for three reasons none of them had anything to do with: `[` and `]` (ADR-138 §6), the `#` that defuses a numeric character reference (§8b), and now the backtick — and a later reader replacing that encoder needs to know it.

So across ADR-137's five, the backtick lands in the form each surrounding's rule takes: `` \` `` in the cell, the heading and the membership entry, which answer to a reader; `%60` in the destination, which answers to a resolver, already written; and nothing in the CSV, which answers to a parser. ADR-138 §5's table gains one member in three rows and none in two.

### 3. One renderer's divergence from the specification moves no rule

This is the part #261 asked for because it generalises, and it is stated as a rule for the next finding rather than as a verdict on this one.

**A rendering hazard moves an escaping rule when the specification the renderers implement makes it one** — when the character is structural in that surrounding under CommonMark, or under GFM where the surrounding is GFM's, and the measurement shows the conforming configurations doing what the specification says. **A hazard present only in one configuration that diverges from the specification is recorded as a measured fact and carries no weight towards a rule.** It is not a tiebreaker, and it is not counted on either side of a cost argument. Where a rule adopted on the specification's ground happens to close the divergent case as well, that is recorded as a consequence and is never cited as a reason.

**A configuration that implements CommonMark but not the grammar of the surrounding a value was written into counts as conforming, and what it does counts wherever the specification applied to what it actually parses predicts it** — so §10b's `commonmark` row, where the reference builds no table, reads an index row as a paragraph, and pairs one backtick in the first column with one in the third into a code span that swallows the link, is weight, and it is weight for §1, being the pair across two values rather than a lone backtick.

Three things make this the right weight rather than merely a cautious one:

- **The tool writes to a specification, not to a list of renderers.** Every record in this family has carried the same open question — which renderers an operator actually opens the tree with — and has been able to leave it open because each decision held in every configuration measured. A rule moved by one divergent renderer is a rule that has answered that question for one application without evidence, and the next divergent renderer, in the other direction, would ask for the opposite.
- **A defensive escape is not free and it is not bounded.** Each costs a plain-text reader a backslash in the file ADR-103 makes a supported way to read the tree, and a renderer that misreads conforming input can misread anything; escaping against one renderer's bugs has no natural stopping point short of escaping every punctuation character in every value.
- **A defensive escape is patching another tool's defect at one remove.** #261 names that as a stance the project already holds; no earlier record states it, so it is not cited here as precedent, and this section is now where it is written down for rendering. The divergence belongs upstream, to the renderer.

**What would change the weight is evidence about which renderers are read, not the severity of the symptom.** If a later measurement establishes that an application operators really open the tree in is the divergent one, a later record may weigh that divergence on that evidence, and should say so in its own title. Until then, a visible failure and a silent one in a single divergent configuration weigh the same, which is nothing.

### 4. So the lone backtick would have been declined, and that is stated so the escape is not misread

Had §10 found only what §8b found — a single backtick, refused in link text by `marked` alone — **the answer under §3 would have been no escape**, and this record would have said so. The escape adopted in §1 is not that answer relaxed. It rests on the pair, which is a hazard in every configuration, and the unconditional form ADR-138 §4 requires is what makes it reach the lone backtick too. That it then closes `marked`'s refusal in both positions the tool composes link text — the membership entry and the index's linked first column, the second of which §10b found and §8b had not — is a consequence, measured (§10d), and nothing in this decision leans on it.

A later reader who finds the backtick escape costly and wants it removed must answer the pair, not `marked`. A later reader who finds another character `marked` alone misreads must answer §3 before proposing an escape for it.

### 5. §9g's residual is declined under the same rule, and ADR-103's no-network claim stays residual in `marked`

ADR-138 recorded, and deliberately did not decide, that `marked` alone reads the escaped `!\[shot\](…)` in the index's linked first column as an `<img>`, and so a page opened in it still fetches an image from a host a value named (§9g). The source there is conforming — CommonMark makes `\[` a literal `[` — and no configuration that follows the specification forms an image from it. Under §3 that is a divergence of one renderer from the specification, and **no escape is written against it**: not a backslash before the bang, which is not structural in CommonMark before an escaped bracket, and not any other.

That leaves ADR-103's claim — the tree resolves every link with no network — restored in six configurations of seven and residual in `marked`, exactly where ADR-138 left it, and it is now left there on purpose. It is the harder case for §3, because the symptom is a network request rather than a visible failure, and that is why §3 says severity is not what moves the weight. What would reopen it is the evidence §3 names: that `marked`, or an application built on it, is what the tree is read in.

## Consequences

**A plain-text reader sees one more backslash, before each backtick.** ADR-103 makes the raw `.md` a supported way to read the tree, so the cost is real, and it is the fifth time this family has taken it. What bounds it is the same as before: a value with no backtick is untouched, and the reader of a value that has one is the reader this most helps — unescaped, a pair of backticks has removed two characters from what that reader's renderer shows, or put backslashes in front of them that the archive never held, and after this the raw file and the rendered page say the same thing.

**A model-written title that uses backticks to mark code loses its code formatting.** That is the decision rather than an accident of it: ADR-134 treats what the model answered as untrusted text to be shown as characters, ADR-138 escaped the model's brackets on the same footing, and a title is a name the index lists rather than prose the tree lets render. The body of a synthesis doc is not touched by any rule here.

**The production change is owed and is not made here.** `escapeLinkText`, `inAHeading` and `inACell` each gain one replacement after the backslash's; `asLinkText` gains nothing, being a call to `inACell`. The javadocs of those three methods, and the enumeration on `escapeLinkText` of what each surrounding escapes, move with the code. No `src/main` file is edited by this record, and the tests that pin it — `DeliverableTest.keepsABacktickedNameFromTurningIntoCode` and `ClusterFileTest.keepsABacktickInAnEntryAndAHeadingReadableAsItself` — are red until that change lands.

**ADR-138 §5's table, after this record:**

| Surrounding | Rule | Folds | Escapes |
|---|---|---|---|
| A table cell | `inACell` | yes | `\` `<` `&` `[` `]` `` ` `` `\|` |
| An ATX heading | `inAHeading` | yes | `\` `<` `&` `[` `]` `` ` `` |
| A membership entry | `escapeLinkText` | no | `\` `<` `&` `[` `]` `` ` `` |
| The CSV manifest | `quoted` | no | RFC 4180 quoting |
| A link destination | `relativeDestination` | no | URI quoting, plus `%28` `%29` `%26` |

**What stays open is what every record in this family has carried**, and §3 now gives it a second job: which renderers an operator actually opens the tree with. VS Code's preview, IntelliJ's, Obsidian and github.com in a browser are unmeasured as applications. The escape adopted here does not depend on the answer — it is correct in all seven configurations measured, and the form it replaces is wrong in all seven for a pair — but the one residual declined in §5 does, as would any later finding §3 applies to, and that measurement is what would reopen it.
