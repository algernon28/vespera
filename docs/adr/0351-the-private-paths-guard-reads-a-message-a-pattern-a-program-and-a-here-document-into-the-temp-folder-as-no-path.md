## Context

The guard reads a Bash command's whole text for paths (ADR-196 §4) and every token of it for a closed `.claude` folder (ADR-215 §3(c)). Some of that text is given to a program as text it never opens: a commit message, a `gh` filter, a `grep` pattern, an `awk` program, the lines of a here-document `cat` copies into a file. Issue [#697](https://github.com/algernon28/vespera/issues/697) records five such commands refused, each costing a retry and a workaround: a `gh … --jq` filter holding `\(`, an `awk` program holding `/^>>>>>>> /`, a `git commit -m` message holding a word that begins with a slash and `\|`, a `grep` alternation holding `\|`, and a here-document writing an issue body to the scratchpad whose lines named files in the hooks and agents folders.

### Read, and not executed

- The Bash reference manual, "Here Documents": "If any part of word is quoted, the delimiter is the result of quote removal on word, and the lines in the here-document are not expanded." So the lines of a here-document whose delimiter is quoted are given to the program as written: no variable, command substitution or arithmetic is run.
- GNU grep's manual: `-e PATTERNS` and `--regexp=PATTERNS` give the pattern, and "If no -e or -f option is given, the first operand is the pattern"; GNU getopt reads an option after an operand too, and takes a unique prefix of a long option's name.
- The gawk manual: `-f`, `-e`/`--source`, `-i`, `-E` and `-l` give the program or a file of it; a program reads or writes a file only through a string or a variable after `getline <`, `>`, `>>` or `|`, or `@include "file"`.
- The jq manual: a program reads a file only by `import` or `include`, or by `modulemeta`, which loads the module its input string names (jq adds `.jq` and refuses `..` in it, but the guard does not lean on that); `-f`/`--from-file`, `-L`, `--slurpfile` and `--rawfile` name files.
- The Bash reference manual: arithmetic is evaluated in `$(( ))`, in `$[ ]` (kept, though no longer documented), in an indexed array's subscript, and in the operands of `[[ … -eq … ]]` and its kin, and an assignment in it assigns; `${NAME=word}` assigns; a word `{NAME}` before a redirect operator assigns NAME a descriptor; `wait -p NAME` and `coproc NAME` assign NAME; and `cd` sets `PWD` and `OLDPWD`.

## Decision

### 1. A flag's text is no path

**In a Bash command, the argument of these flags is not read as a path**:

- `git`'s `-m` and `--message`, after the subcommands `commit`, `tag` and `merge`, and after `stash` where the first word after it that is no option and no option's argument is `push` and no `-m` stands before it, or where there is no such word (`stash show` and `stash list` read `-m` as taking no argument, so after any other word nothing is taken out of the segment); and `-m` at the end of a cluster of letters that subcommand reads as taking no argument (`git commit -am`, `-sm`; in `git merge`, `-s` takes a strategy, so `-sm` gives no message). The subcommand is the first word after `git` that is no option, where every option before it is `-C` or `-c` and the word after it, `--name=value`, or one of the options of `git` that take no argument (`-p`, `-P`, `--no-pager`, `--bare`, `--literal-pathspecs` and their kin); any other, `--git-dir`, `--work-tree` and `--namespace` among them, means nothing is taken out of the segment. After the subcommand each option is read as that subcommand reads it, from a table of its options: one that takes an argument (`-C`, `-c`, `-F`, `-t`, `--author`, `--date`, `--cleanup`, `--fixup`, `--squash`, `--trailer`, `--pathspec-from-file` and the rest) takes the next word, a long name may be written by a unique prefix, and at an option the table does not hold, a word whose head the guard does not know and that may become one (`$o`, `-{C,}`), or a word that holds a `$` outside quotes anywhere, which Bash may split into more words than one, one of them an option (`x$o`), nothing more is taken out; `"x$o"`, inside double quotes, is one word, and a wildcard, brace or `~` after a head the guard knows keeps that head on every word Bash makes of it, so each is read as before;
- `gh`'s `--jq`, `-q` and `--body`, after `gh api`, and after the subcommands of `gh issue` and `gh pr` that have them: `create`, `comment`, `edit`, `view`, `list` and `status` of both, and three of `pr`'s own: `checks`, `merge`, and the one that approves a pull request or asks for changes to it. The command's path is the words right after `gh`, each written whole; after any other, an alias or an extension among them, nothing is taken out. After the path each option is read as that command reads it, from a table of its options, as pflag reads them: one that takes an argument (`api`'s `-H`/`--header`, `-X`/`--method`, `-p`/`--preview`, `-t`/`--template`, `-f`, `-F`, `--hostname`, `--cache` and `--input`; `issue`'s and `pr`'s `-R`/`--repo`, and `-t`/`--title`, `-B`, `-H`, `-a`, `-l`, `-m`, `-p`, `-r`, `-F`/`--body-file` and the rest where that command takes an argument by them) takes the next word whatever it is, `--jq`, `-q` and `--body` among them, which then give no text; a short letter that takes one takes the rest of its cluster where any is left; a long name is read only written whole, as pflag reads it; and at an option the table does not hold, a word whose head the guard does not know and that may become one (`$o`, `{-H,}`), a word headed by `-` that the guard does not know all of (`-{H,}`), or a word that holds a `$` outside quotes anywhere (`x$o`), nothing more is taken out;
- `grep`'s, `egrep`'s and `fgrep`'s `-e` and `--regexp`, and `-e` at the end of a cluster (`grep -ne`), read as §2 reads `grep`'s options.

The argument is the next word, or the text after the `=` of `--message=`, `--jq=`, `--body=` and `--regexp=`. It is taken out only where it is a literal the shell gives the program as one argument: one single-quoted string, one double-quoted string with no `$(`, `${`, `$[` or backtick, or a bare word with no quote, `$`, backtick, wildcard, brace or `~`. The program is the segment's first word that is no reserved word (`!`, `{`, `if`, `then`, `do` and their kin), no `time`, no one `-p` and then one `--` after `time`, as Bash takes them, and no assignment, bare. No flag is read so after a word `--`. §1 and §2 read the words Bash gives the program: a redirect operator, its target (but for `<<`, whose delimiter is in its own text) and a word of digits alone against the operator after it that Bash reads as a descriptor, a number an int holds, no more than 2147483647 (the `2` of `2>&1`; larger digits stay an argument), are taken out of them wherever they stand, as Bash takes them out, so an option that takes an argument takes the word after a redirect's target, and a target is never a flag's argument or an operand.

### 2. A single-quoted pattern or program is no path

**In a Bash command, the first operand of `grep`, `egrep` and `fgrep`, of `awk`, `gawk` and `mawk`, and of `jq` is not read as a path where it is single-quoted and no option gives the pattern or the program.** Every word of the segment is walked, as getopt reads it, against the program's whole set of options, those that take no argument among them: a short letter or long name that takes an argument takes the next word, a short letter that takes one only joined to it (`awk`'s `-d`, `-D`, `-L`, `-o` and `-p`) takes the rest of the word, a long name is the name itself where it is one (`grep --binary`, which takes nothing) and else a unique prefix of one, and `--` ends the options. A long name or short letter the program does not have, a prefix of more than one name, a word whose head the guard does not know and that may become an option (`$o`, `*.md`, `-{f,}`), and a word that holds a `$` outside quotes anywhere, which Bash may split into more words than one, one of them an option (`x$o`), are read as giving the pattern; `"x$o"`, inside double quotes, is one word, and a wildcard, brace or `~` after a head the guard knows keeps that head on every word, so each is read as before. Where any word gives the pattern, the program or a file of either (`grep`'s `-e`, `-f`, `--regexp`, `--file` and `--exclude-from`; `awk`'s `-f`, `-e`, `-i`, `-E`, `-l`, `-W` (mawk's `-W exec` names a file of the program), `--file`, `--source`, `--include`, `--exec` and `--load`; `jq`'s `-f`, `-L`, `--from-file`, `--library-path`, `--slurpfile`, `--rawfile`, `--argfile` and `--run-tests`), no operand is taken out, since the first is then a file.

An `awk` program is taken out only where it holds no `"`: it names a file only in a string. A `jq` program is taken out only where it holds none of `import`, `include` and `modulemeta`. `sed` is not among these: its program reads and writes files by its `r`, `R`, `w` and `W` commands and runs one by `e`, and ADR-347 keeps its refusal on Windows.

### 3. A here-document `cat` writes into the temp folder is no text the guard reads

**In a Bash command, the lines of a here-document are read neither for paths nor for a closed `.claude` folder where all of this holds**:

- its delimiter is quoted, `'EOF'` or `"EOF"`, so its lines are not expanded;
- its line is the segment alone, from the line's start to the line break: `cat`, then `>` or `>>` and the file, and the here-document's operator before or after them, and nothing else;
- the file is one word, a path from a root, or a variable of the environment and a path after it, with no `.` or `..` name, no other `$`, no `~`, wildcard or brace, and it lies beneath the folder the allow list names `${TEMP}`, where the scratchpad lies;
- the variable is `TEMP`, `TMP` or `TMPDIR`, which Bash never assigns by itself (as it does `PWD`, `OLDPWD` and `_`), spelt as an environment key spells it, case for case, as Bash reads it (`$temp` is not `$TEMP`, though Windows gives Node either); a command §4 lets anything be taken out of assigns none of them, so its value is the guard's own.

The lines run from the one after the operator's to the delimiter's, which is taken out too. The line of `cat` is read as before, so the file is judged as every path is, a closed `.claude` folder and a deliverable tree included, and every line after the delimiter is read as before.

### 4. Text is taken out only of a command whose programs are the ones their names say

These are found by a cut of the command into its words and segments as Bash cuts them: at `;`, `&`, `|` and the line break outside quotes, a `#` at a word's start beginning a comment. Where that cut may not be Bash's, or an expansion in the command may assign or run, nothing is taken out and the command is read as before: a `(`, `)` or backtick outside quotes; a `$(`, `${`, `$[` or backtick inside double quotes; a `$'`, `$"`, `$(`, `${` or `$[` outside quotes; a quote left unpaired; a backslash before a line break or at the end; a here-string; and a here-document whose delimiter is not quoted, whose lines Bash expands, in the shell itself where its program is a builtin. The lines of a here-document whose delimiter is quoted are no words of the cut. In a PowerShell command nothing is taken out.

§1 to §3 trust that a program's name is that program and that §3's variable holds the guard's value. **Text is taken out only where every segment of the command is one of these, and else nothing is taken out of any of it**:

- a segment whose program, its name written whole and its quotes taken off, is one of `git`, `gh`, `grep`, `egrep`, `fgrep`, `awk`, `gawk`, `mawk`, `jq`, `cat`, `cd`, `echo`, `true`, `ls`, `head`, `tail`, `wc` and `sort`: each but `cd`, `echo` and `true` runs as a program of its own and changes nothing in the shell, and those three assign no name but `PWD`, `OLDPWD` and `_`, which neither a program's name nor §3 is read by;
- a `for` loop whose name is lower-case letters, digits and `_`, a letter first: no variable of Bash's own is so spelt, nor any §3 reads;
- a segment with no program: redirects, or the reserved words `!`, `{`, `}`, `if`, `then`, `elif`, `else`, `fi`, `do`, `done`, `while`, `until` and `time` alone;

and where no word before a segment's program is an assignment (`NAME=`, `NAME+=` or `NAME[…]=`, whose subscript Bash reads as arithmetic), and no word `{NAME}` stands against a redirect operator, which assigns NAME the descriptor. So a function, an alias, `hash`, `eval`, `source`, `trap`, `export`, `declare`, `read`, `printf -v`, `let`, `wait -p`, `coproc`, `[[ ]]`, `command`, `env`, a program named by a variable (`$e`), and every other builtin, keyword and program leave the command read whole: the list says what is trusted, not what is not.

What is taken out is blanked, each character but a line break made a space, so that every other text keeps its offset. The guard reads the blanked command for paths, ADR-347's index form found in the command as written; it reads the command with only §3's lines blanked for a closed `.claude` folder; and it tells ADR-264 §3's listed commands and ADR-212's counting command from the command as written.

- **C771 to C791**, refused (§1, §2): `git stash show -m` and `git stash list -m` before `--output=` of a file outside the allow list; `grep` of a quoted file outside the allow list before `-{f,}`; `git commit -{-,} -m` of one, which Bash makes `--`, so the file is a pathspec; `grep` of one after `time -x` and after `time -p -p`; `grep` of one before `x$o`, and `git commit x$o -m` of one, which Bash may make `x --`; and `gh pr create -t --body`, `gh api -t --jq`, `gh api {-H,} --jq` and `gh api x$o --jq`, each before `--body-file=` or `--input=` of one; `gh api -t >/dev/null --jq` and `gh pr create -t 2>&1 --body` before one, `git commit -C >/dev/null -m` of one and `grep pat --label >/dev/null -e` of one; and `grep --label` and `jq --arg a` written by `>` into a file outside the allow list; and `gh api --jq`, `git commit -m` and `grep -e` given digits more than an int holds against `>/dev/null`, before or of one; C771 to C776 the third draft's, C777 and C778 the fourth's, C779 to C782 the fifth's, C783 to C788 the sixth's, C789 to C791 the seventh's (Measured).

Against the draft at commit e4e7eff5, on Windows, C501 to C505, C512 to C514, C516, C518, C519 and C521 to C527 fail, and the rest pass (Measured).

## Decided here

1. **§1 and §2 name programs and flags, and no flag is skipped for every program.** `-e`, `-q` and `-m` take no argument in `cat`, `head`, `sort`, `git am`, `git stash show` and `git stash list`, and a file after them is the file read; a table by program, and for `git stash` by its subcommand, is what keeps it read (C609 to C611, C771, C772). So is a table of every option of each `gh` command: an option that takes the next word takes `--jq` or `--body` too, and the word after is then `gh`'s own (C779, C780). And each table is read against the words Bash gives the program, with no redirect among them: an option's value is the word after a redirect's target (C783 to C788), and digits are a descriptor only where Bash reads them as one (C789 to C791).
2. **§1 and §2 take a text out of the reading for paths and not of ADR-215 §3(c)'s.** The issue's commands are refused for paths, and no command of it for a message naming a closed folder; a message that names one still goes in a file with `-F`, as AGENTS.md has it, and Q108 stands.
3. **§3 takes the lines out of both readings, and only for `cat` into the temp folder.** The fifth command is refused by ADR-215 §3(c) alone. A here-document's lines given to `cat` are copied, not run, where its delimiter is quoted; the file is the one thing written, and is judged. Into the temp folder it is what the Write tool may already write there; elsewhere, or by another program, nothing is taken out.
4. **§4: text is taken out only of a command whose every program is on a fixed list, that assigns nothing, and whose cut is the shell's.** A command the cut cannot read is read whole, as before this record. Where it can be read, §1 to §3 trust that `grep`, `git`, `gh`, `awk`, `jq` and `cat` are those programs, that each reads its options as its table has them, and that `$TEMP` holds the guard's value. The first two drafts listed what breaks that trust, and each gate of PR #709 found forms the list left out, more than thirty between them (Measured): Bash assigns by more builtins, keywords and expansions than a record can be shown to have named whole. So §4 lists what is trusted instead: programs that run on their own and change nothing in the shell, three builtins that assign no name the guard reads by, and a `for` loop over a name of none of Bash's or §3's; and it refuses every assignment, `{NAME}` redirect and expansion that may assign or run. Anything not on the list is read whole, so a form no gate has found yet costs a retry, not a leak. `TEMP`, `TMP` and `TMPDIR` alone name §3's folder, since Bash assigns `PWD` by itself. What lies outside the command, a program installed in place of one of these or a function a shell profile defines, is not decided here (below).
5. **A script written by §3 and run by a later line is not read.** `cat > "$TEMP/x.sh" <<'EOF'` and then `bash "$TEMP/x.sh"` runs lines the guard did not read; so does a file the Write tool wrote and a later command runs, which ADR-196 §5 already lists as not covered ("a path a command builds at run time"). This adds no kind of call the guard did not already let through in two.

## Consequences

- **The five commands of #697 are let through on every platform.**
- **A real path argument and a real write target are read as before**: beside a skipped flag or operand, after a flag of the same letter in another program, and as the file a here-document is written to.
- **A message that names a closed `.claude` folder is still refused**, and still goes in a file with `-F`.
- **On Windows a message, a pattern or a single-quoted `awk` or `jq` program holding a name made only of dots, spaces or a stream name, or one letter and a colon, is let through**; the same text elsewhere in a command is still refused there (ADR-217 §2, ADR-196 §4). A `sed` program is still refused there.
- **A command that runs any program off §4's list, `sed`, `find`, `xargs` or `node` among them, or that assigns anything, has nothing taken out**, and is read whole as before this record; such a command that needs a message or a pattern read as text is split, or its text goes in a file.
- **The installed guard reads none of this until the operator installs the draft** (ADR-215 §7).
- **Nothing under `src/main` changes, and no run id moves.**

## Alternatives weighed

- **Skipping the flags for every program.** Rejected: Decided here 1.
- **Skipping any quoted argument that looks like a regular expression.** Rejected: a quoted path holds the same characters as a pattern, `.` and `/` among them, and "looks like" is no rule a test can hold; the program's own reading of its words is.
- **Skipping a here-document's lines into any file the allow list lets through.** Rejected: the issue asks for the scratchpad, and a file inside the checkout is one a later agent may run or load; the temp folder is where the scratchpad lies.
- **Taking the skipped text out of ADR-215 §3(c)'s reading too.** Rejected: Decided here 2.
- **Listing what changes what a name runs, and taking text out of every other command.** The first two drafts did so. Rejected: Decided here 4.
- **Reading a here-document's lines whose delimiter is not quoted for `$` and backtick, and cutting only where they hold one.** Rejected: a quoted delimiter is what AGENTS.md and §3 ask for, and a body read for expansions is a second cut to keep right; refusing the cut costs only a command already read whole before this record.

## What this does not decide

- Whether `/tmp`, which Git Bash mounts on the temp folder, names it for §3 on Windows; there the guard reads no rooted POSIX path (ADR-196 §5), so a here-document into `/tmp/x` is read as before. On Linux, where the temp folder is `/tmp` unless `TEMP` or `TMPDIR` names another, `/tmp/x` is a path from a root beneath it, and §3 takes its lines out.
- A file joined to a short option, as `-O../outside/doc.txt` after `git stash show -m`: the guard reads no path in such a word, at commit e4e7eff5 as under this record (Measured, by a probe of C771's form), and whether it should is ADR-196 §4's and a later record's.
- Whether other programs and flags join §1 and §2's tables, or other programs §4's list; each is a later record.
- What a program does that stands in PATH in place of `grep`, `git`, `gh`, `awk`, `jq` or `cat` before the command runs, or a function or alias the shell defines from a profile: the guard reads the command, not the machine, as ADR-196 §5 has it for a path a command builds at run time.
