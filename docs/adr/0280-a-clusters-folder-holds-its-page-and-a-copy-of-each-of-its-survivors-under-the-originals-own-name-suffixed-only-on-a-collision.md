## Context

On 2026-10-18, charting map [#551](https://github.com/algernon28/vespera/issues/551), the operator settled the per-cluster deliverable: `<partition>/<cluster>/` holds the cluster's page and the verified copies of that cluster's survivors, the index stays at the tree's root, and a copy keeps its original's file name, with an occurrence-id suffix only on a collision.

**What the tree is today.** A survivor's copy is `documents/<occurrence>-<slug40>.<ext>` (ADR-274 §2.1), flat, collision-free by construction, its path bounded whatever the archive's depth, and free of every character a path parser can refuse. ADR-274 refused "copies under their root-relative paths" for those reasons. A cluster's page is `<partition>/<cluster>.html`, and its pictures lie in `<partition>/<cluster>/`, a folder named from the page's stem (ADR-149 §3). `documents.csv`'s `copy` column and the index's paragraph both name `documents/`.

**What fixes a cluster's membership.** Each survivor is in exactly one cluster under a generation run's arrangement: `document_cluster`'s primary key is `(occurrence_id, run_id)`. So no survivor is copied twice, and the members of a cluster, their occurrence ids and their root-relative paths, are fixed for the tree a generation run draws.

**What a collision suffix costs.** A name that carries a suffix only on a collision depends on the cluster's other members, where ADR-274 §2.3 and §2.4 rest on "the name follows from the survivor alone": a copy at its name is trusted on resume and neither it nor its original is read.

**What the path budget was.** ADR-274 §2.7 allows the working directory 69 characters, from `deliverable/`, a run id of 64, folders of 45 and a copy named `<id>-<slug40>.<ext8>.part`; ADR-276 §1 turns that into 146 for a named root. An original's file name has no such bound, and Windows compares names without regard to case.

**What a folder's name is.** A partition folder and a cluster's name are the order prefix and a slug (ADR-112): a rendering, not identity. A changed cluster label is a new arrangement, with a generation run and a tree of its own (ADR-276 §3), and nothing is deleted (ADR-103).

**What two earlier records say of images.** ADR-149 §4 and ADR-150 §4 say an image survivor is not copied, which ADR-274 §2 and the code contradict: every survivor listed is copied.

**What ADR-276 §6 owes.** A tree drawn in ADR-274's flat layout and redrawn in a new one keeps its old `documents/` folder, and the closing line says it can be deleted by hand. ADR-276 states the rule and could not test it, there being no second layout.

## Decision

### 0. The cluster's folder and what it holds

**`<partition>/<cluster>/` is named as ADR-112 and ADR-274 §1.2 named the page's stem**, the order prefix and the cluster label's slug cut to 40 characters, without `.html`. It holds:

- **the cluster's page, `index.html`**, and, where #571 splits it, `index-2.html`, `index-3.html` and on;
- **the page's pictures**, until #560 inlines them, at ADR-149's `<16 hex>.<ext>` names: the folder they already lay in, so an `<img>` on the page names the file alone, `<hex>.<ext>`;
- **the verified copy of each of the cluster's survivors**, named by §1.

```
<deliverable root>/
  index.html                          the arrangement, whole, and what produced it
  documents.csv                       one row per survivor
  vespera-deliverable.txt             the marker (ADR-276 §3)
  <partition>/<cluster>/index.html    one page per cluster
  <partition>/<cluster>/<hex>.<ext>   the pictures that page shows (ADR-149)
  <partition>/<cluster>/<copy name>   a verified copy of each of the cluster's survivors
```

**The tree's `index.html` links `<partition>/<cluster>/index.html`.** `documents/` is no longer written.

**`documents.csv`'s `copy` column is `<partition>/<cluster>/<copy name>`**, from the tree's root with `/` between its parts, or nothing where no copy stands. A copy's name keeps the commas and quotes of its original's, so the column is quoted by RFC 4180 as the path columns are, behind ADR-235's single quote where it would begin as a formula: a cell holding `,`, `"` or a line break is wrapped in `"`, a `"` in it doubled, and its row keeps all eleven fields. **The index's paragraph stops naming `documents/`**: it says that each group's folder holds its page and a copy of every document listed on it, checked against the digest taken when it was converted.

**ADR-149 §4 and ADR-150 §4 are struck where they say an image survivor is not copied.** ADR-274 §2 governs: every survivor listed is copied, images included.

### 1. A copy's name, and what counts as a collision

1. **It starts from the original's file name**: the last element of its root-relative path, everything after its last `/`, as written.
2. **It is made safe on every operating system**, since the tree may be carried to Windows, in this order:
   - each of `< > : " / \ | ? *` and each control character, U+0000 to U+001F, becomes `_`;
   - trailing dots and spaces go;
   - a name whose part before its first dot, its trailing spaces not looked at, is a Windows device name, `CON`, `PRN`, `AUX`, `NUL`, `COM0` to `COM9`, `COM¹`, `COM²`, `COM³`, `LPT0` to `LPT9`, `LPT¹`, `LPT²` or `LPT³`, without regard to case, gets a leading `_`: `CON .txt` is a device name, and becomes `_CON .txt`;
   - a name left empty is the survivor's occurrence id, in decimal.
3. **It is cut** (§3). **The device rule and the empty rule hold of the name as it stands after the cut and after any suffix (§1.6)**, and not only of the name before it: a cut whose trailing dots and spaces go may leave nothing, or a device name. `' '`×100 followed by `abc` is cut to nothing and is the occurrence id; `AUX`, 120 spaces and `z.pdf` is cut to `AUX.pdf` and becomes `_AUX.pdf`. A suffix puts `~` before the extension, so a suffixed name is neither.
4. **Two collision keys.** The decomposed key is the name in Unicode normalisation form D, lower-cased, then upper-cased, both with `Locale.ROOT`, and put in normalisation form C: NFC(upper(lower(NFD(name)))). The per-unit key is the name with each UTF-16 unit upper-cased on its own by `Character.toUpperCase` and nothing normalised, as NTFS compares names. **Two names collide when a key of one equals a key of the other.**
   - **The per-unit key is there for what decomposing parts.** `U+03B1 U+0345 U+0342 .pdf` and `U+03B1 U+03B9 U+0342 .pdf` upper-case unit by unit to the same `U+0391 U+0399 U+0342 .PDF`, so NTFS holds them as one file; but form D sorts U+0345 after U+0342 in the first, so their decomposed keys are U+0391 U+0342 U+0399 and U+0391 U+0399 U+0342 and differ. By the decomposed key alone both would keep their plain names, the second copy would be taken as standing (ADR-274 §2.4) and its link would open the first's bytes.
   - **The name is decomposed before it is cased for the combining ypogegrammeni, U+0345**, the iota subscript, the one combining mark that upper-cases to a letter, `Ι` (U+0399). In form C it may stand composed into its letter or after it behind another mark, and upper-casing writes its `Ι` where it stood: `ᾼ͂.pdf`, U+1FBC U+0342, is composed as written, and `ᾷ.pdf`, U+1FB3 U+0342, is composed to U+1FB7; upper-cased they are U+0391 U+0399 U+0342 and U+0391 U+0342 U+0399, and keyed in form C first, both would keep their plain names. NTFS upper-cases each UTF-16 unit, U+1FB3 to U+1FBC, and APFS's case-insensitive form decomposes and folds both to U+03B1 U+0342 U+03B9: each holds the two as one file, so the second copy would be taken as standing (ADR-274 §2.4) and its link would open the other survivor's bytes. Decomposed, U+0345 stands after every other mark on its letter, since its combining class, 240, sorts it last, and both names key to U+0391 U+0342 U+0399.
   - **The lower-casing is there for the capitals upper-casing leaves alone.** `ϴ` (U+03F4) and `ẞ` (U+1E9E) are capitals of `θ` and `ß`, and upper-casing keeps each as it is while it takes `θ` to `Θ` and `ß` to `SS`: by upper-casing alone, `θ.txt` and `ϴ.txt`, and `ß.txt` and `ẞ.txt`, would each keep their plain names. A file system that folds case by Unicode's case folding, APFS's case-insensitive form among them, holds each pair as one file, so the second copy would be taken as standing (ADR-274 §2.4) and its link would open the other survivor's bytes. Lower-cased first, `ϴ` is `θ` and upper-cases to `Θ`, and `ẞ` is `ß` and upper-cases to `SS`.
   - **The key is composed at the end**, so that what casing gives back is one spelling whatever spelling it came from: `İ.txt` and `i̇.txt`, and `ΐ.txt` and `Ϊ́.txt`, collide, as they do on a file system that normalises. `İ` lower-cases to `i` and a combining dot above, and so meets `i̇`.
   - **Over every single code point followed by `.txt`, this key puts together every pair of names that NFC(upper(lower(NFC(name)))) did, and parts none of them**; it puts more together only where marks follow a letter, as `ᾼ͂` and `ᾷ` do. A character's key is its lower case's and its upper case's, `İ` excepted, whose lower case by itself is `i`, and which case folding keeps apart from `i` too, as this key does.
   - **The keys are held against two file systems' comparisons, not every file system's**: NTFS's, which upper-cases each UTF-16 unit by its own table and does not normalise, and which the per-unit key follows, and APFS's case-insensitive form's, which decomposes and folds case, and which the decomposed key follows. A file system that folds by another table may hold as one file two names this key keeps apart (What this does not decide). A key that matches too much, as `ß` and `SS` do, or a key of one kind meeting one of the other, costs only a suffix.
5. **The reserved names**, which a copy always yields to, compared by the same key: `index.html`; `index-<digits>.html`, the digits one or more of `0` to `9`; the names of the pictures written into the folder for the cluster's page; and `<another copy's name>.part`, read as the name, made safe and cut, of any other survivor of the cluster, and any name already given in the folder, followed by `.part`.
6. **Who keeps the plain name.** Within one cluster's folder the survivors are taken in ascending occurrence id. Of the survivors whose names collide, the lowest occurrence id whose name collides with no reserved name keeps its plain name; a name that collides with a reserved name is kept by none of them. Every other survivor of those whose names collide gets **`~<occurrence id>` before the extension**: `report.pdf` becomes `report~42.pdf`, and a name with no extension takes it at the end. The plain names kept count as given before the first suffix is, so a suffixed name is compared with every one of them. A suffixed name that still collides with a reserved name or a name already given, or that followed by `.part` is a name already given, gets `~<occurrence id>` again, `report~42~42.pdf`, until it is free: of members 1 `report.pdf`, 2 `REPORT~5.PDF.part` and 5 `REPORT.PDF`, 5 is `REPORT~5~5.PDF`, since `REPORT~5.PDF`'s part would be written over 2's copy.
   - **The repeating ends.** While some of the original's stem is left, an attempt may repeat an earlier one, since each suffix cuts the stem further (§3). Once the stem is empty, each attempt is the one before with one more suffix, strictly longer, and the names a folder gives are finite, so one is free. A stemless name may pass 100 code units, and six members suffice to bring it about. A name that then holds more than 255 UTF-8 bytes with `.part` after it is not made: that copy is `not-copied`, recorded and never thrown (ADR-274 §2.3). `Copies` counts the name's bytes itself, before the original is opened or any `.part` written, and does not wait for a file system to refuse it: one that bounds a name by 255 UTF-16 units, as NTFS does, would take a name ext4 refuses, and the outcome would move with the disk. So such a copy is `not-copied` even where its original is gone or the drive has no room, and nothing is written for it.
   - **The extension** is the name's last `.`-part, everything after its last dot, kept as written: it is not lower-cased, as ADR-274 §2.1's was.

### 2. How resume finds a copy

**A copy's name is a function of the survivor and its cluster's members**: their occurrence ids and their file names, and the names of the pictures the cluster's page shows. All are fixed for the tree, since membership is `document_cluster` under the tree's generation run and a picture's name is its own bytes'.

So **before a cluster's first copy, the writer works out every name in that cluster from what is recorded alone**, reading no original. ADR-274 §2.4 then holds unchanged: a file at the name worked out was put there by §2.2's move, is taken as copied, and neither it nor its original is read. ADR-274 §2.3's and §2.4's "the name follows from the survivor alone" reads "from the survivor and its cluster's members, both fixed for the tree".

**A name the platform's path parser refuses is that survivor's own failure**, beside ADR-274 §2.3: the copy's path is resolved inside the handling of that one survivor, so an `InvalidPathException` or any other failure to make the path is its `not-copied`, recorded and never thrown, and the next survivor is copied.

**What is held across the drawing is one folder string for each cluster, its path from the tree's root, and the name of each copy a collision changed**, and, in `Deliverable.writeTo`, the paths of the partition and cluster folders this drawing wrote, one string each, until §4's listing of what was left behind, for ADR-220's reason: the pages and the manifest written after the copies name them. Every other copy's name is worked out again from its survivor alone, its original's name made safe and cut (§1.2, §1.3), as `CopyNames.plainName` does, and is not held. What is held grows with the clusters and the renamed copies, not with the survivors. While a cluster's copies are made, that cluster's names are worked out together and held, as many as it has survivors, and let go when they are made. A name worked out again from the same members is the same name.

**One partition's entry-picture HTML is held until that partition's pages are written**, for ADR-223 §9's reason: the tree goes through one seed partition at a time, and what it holds is bounded by the largest. A copy yields to a picture's name (§1.5), so each cluster's pictures are written before its first copy, and the pages, written after the partition's copies, show what each entry's pictures were without asking the source again (ADR-149 §9). `EntryPictures.writeFor` holds one string for each survivor of the partition, `""` where it shows no picture, which `EntryPictures.appendUnder` takes as its entry is written, and `EntryPictures.forgetPrepared` lets go of the rest at the partition's end. An entry with no picture is held as `""` and not left out: `appendUnder` handed no string for a survivor writes and shows its pictures afresh, and so asks the source a third time, where ADR-149 §9 asks it once in each of two passes.

### 3. The path budget: names are cut, not paths

- **A whole copy name is at most 100 UTF-16 code units, and with `.part` after it at most 255 UTF-8 bytes**, suffix and extension included: 255 bytes is the longest name ext4, XFS, Btrfs and APFS hold in a folder, and a copy is written as its name and `.part` before it is moved into place. `文`×83 and `.pdf`, 87 units, is 258 bytes with `.part`, and is cut to `文`×82 and `.pdf`.
  - The stem is cut at a code point's boundary, a whole code point at a time, so no lone surrogate and no part of a character's UTF-8 is left, and dots and spaces the cut leaves at its end go.
  - The extension is kept whole where it is at most 16 code units, the dot before it not counted. Otherwise the name is taken to have no extension, and the whole of it is the stem.
  - The cut is made before collisions are looked for. A suffix that takes a name past either bound cuts its stem further: the stem of the original name is cut to leave room for every suffix the name carries.
- **No cut depends on where the tree lies**, so a name does not move with the root or the working directory, and resume holds wherever the tree is drawn.
- **A copy no longer has a fixed bound below 260 characters.** ADR-274 §2.7's 69 and ADR-276 §1's 146 still bound the index, the pages and the pictures. Below a deep root a copy may pass 260; the JDK writes it (ADR-103), and what may fail is another program.
- **ADR-274 §2.5's survey changes in three places.**
  - **The count before the first copy is every survivor listed and the bytes their originals hold**, and no longer the survivors with no copy at their name: a copy's name is known only once its cluster is reached (§2), so whether it stands is not known before. It bounds what will be copied.
  - **A copy already standing moves the counter of survivors copied on**, as a copy made or failed does, so the counter of a redrawing reaches its total and does not stall.
  - **After the last copy, the count of copies standing, made or kept, at an absolute path longer than 259 characters is a line of its own**, written only where the count is above 0. Its every argument is a number, and it names no path and no document (ADR-274 §8). It tells the operator to name a shorter deliverable root in `vespera.deliverable-root`.

### 4. What an earlier drawing leaves behind

- **A cluster's folder changes its name within one tree only when the naming rule in `deliverable` changes.** A changed cluster label is a new arrangement, and so a new generation run with a tree of its own (ADR-276 §3). Nothing is deleted (ADR-103, ADR-276 §3).
- **After drawing, the writer lists the tree's top level and each partition folder it wrote.** A folder this drawing did not write counts as left behind. A file is not counted, and nothing inside a folder this drawing wrote is looked at.
- **The closing line gains one clause where anything was left behind**, as ADR-276 §6 has it, after the count of documents not copied and before the line's last full stop:
  - `documents/` is named: *"; documents/ holds an earlier layout's copies and can be deleted by hand"*;
  - any other folder left behind is counted and not named, since a cluster's folder is named from a cluster label a model wrote (ADR-274 §8): *"; N folders left by an earlier drawing can be deleted by hand"*, `folder` in the singular for 1;
  - where both were left, the second follows the first after *", and "*: *"; documents/ holds an earlier layout's copies and can be deleted by hand, and N folders left by an earlier drawing can be deleted by hand"*;
  - with nothing left behind, or where this invocation drew no tree, there is no clause.
- **This pays ADR-276 §6's debt**: the clause, and its test for a tree drawn flat and redrawn per cluster.

### 5. Links

- **An entry links `./<copy name>`**, every UTF-8 byte of the name outside RFC 3986's unreserved set, `A`–`Z`, `a`–`z`, `0`–`9`, `-`, `.`, `_` and `~`, percent-encoded with two upper-case hexadecimal digits. An original's name carries spaces, `#` and `%`. The destination is then escaped by ADR-274 §1.3's rule, which changes nothing in it.
- **The link's text stays the root-relative path**, escaped as ADR-274 §1.3 has it.

### 6. Where it is written

Every rule above lies in `deliverable`, one class for each as ADR-213 has it, and the closing line in `pipeline`:

- **`deliverable.CopyNames`**, package-private: `static final int LONGEST_NAME = 100`; `static final int LONGEST_NAME_IN_BYTES = 255`; `static Map<OccurrenceId, String> of(List<ListedSurvivor> members, Set<String> pictureNames)`, every name in one cluster's folder by §1 and §3, from the members in any order and the names of the pictures written into the folder, reading no file; and `static String plainName(ListedSurvivor member)`, the name where nothing collides, from the survivor alone.
- **`Copies.copyAll(Path clusterFolder, List<ListedSurvivor> members, Set<String> pictureNames)`** takes the place of `copyAll(List<ListedSurvivor>)`, working out the cluster's names before its first copy and copying into its folder, by handing them to **`Copies.copyAllAs(Path clusterFolder, List<ListedSurvivor> members, Map<OccurrenceId, String> names)`**, package-private, which copies each member under the name `names` gives it and is where §1.6's bound is tested: a name that with `.part` holds more than `CopyNames.LONGEST_NAME_IN_BYTES` UTF-8 bytes is that member's `not-copied`, told to `DeliverableProgress.survivorNotCopied`, before its original is opened, and the next member is copied. The static `Copies.nameOf` and `Copies.pathOf` go, a name being no function of one survivor: `Copies` keeps what §2 holds, and the page and the manifest ask it for a member's name and its path from the tree's root, the name kept where a collision changed it and `CopyNames.plainName` otherwise. `Copies.DIRECTORY_NAME` names the earlier layout's folder, for §4.
- **`EntryPictures.appendUnder(StringBuilder page, ListedSurvivor member, Path folder)`** takes the place of the form naming a picture directory beside the page: the pictures are written into `folder`, the page's own, and shown by their file names.
- **`DeliverableProgress.copiesAtALongPath(long copies)`**, told once, after the last copy, of §3's count, which `pipeline` writes as its own line only where it is above 0; `DeliverableProgress.toCopySurvivors` told every survivor listed, and `survivorAlreadyCopied` told once for each copy that stands, as §3 has it; and **`DeliverableProgress.leftBehind(boolean documentsFolder, long otherFolders)`**, told once, after the index and the manifest are in place, of §4's listing. Both take only primitives (ADR-274 §8).
- **`NextAction.DeliverableSummary(Path tree, int clustersLeftUnwritten, OptionalInt documentsNotCopied, boolean documentsFolderLeftBehind, int foldersLeftBehind)`**, the generation step handing what it was told to the closing line through the job's execution context, as it hands the count of documents not copied (ADR-274 §7).

### 7. What the documents say

- **`CONTEXT.md`**, in this change: **Copy** is put in its cluster's folder under its original's name, made safe and cut to 100 code units and to 255 bytes with `.part`, suffixed only on a collision; **Cluster folder** is added.
- **The implementer's, in the change that builds this**: README's "Where things live", which names `documents/`, and its "Where the run ends", which says how a copy is named and cut and what the survey of the copies writes; `AGENTS.md`'s sentence keeping agents from a copy "in a deliverable's `documents/`", which reads "in a deliverable's cluster folders", and its list of what is still held, which gains a folder's path for each cluster and each copy name a collision changed; `docs/architecture.md` §1's 6b; and `docs/running-stage-by-stage.md`'s stage 6b.

### 8. No run id moves

The change lies in `deliverable`, which no stage's version names (ADR-274 §5), and in `pipeline`'s closing line and generation step, which no stage's version names either (ADR-222). `profile` does not change, and no run's `config_consumed` gains a value. **The next invocation that reaches the tree redraws it in place in the new layout** (ADR-274 §6), and copies every survivor again under its new name.

## Decided here

1. **The original's own name, with a suffix only on a collision** (§1), where every copy could have carried its occurrence id: a reader sees the file as it was called, and the id appears only where two names would meet.
2. **Two keys without case, on every operating system: one decomposed, lower-cased before it is upper-cased, and composed at the end, and one upper-cased unit by unit as NTFS does** (§1.4): the tree is carried to Windows, whose NTFS upper-cases each unit, to file systems that fold case, `ϴ` into `θ` and `ẞ` into `ß` among them, and to file systems that decompose a name before they fold it, as APFS's case-insensitive form does, so that an iota subscript, U+0345, stands after its letter's other marks whichever way it was written; and a key that matches too much costs a suffix and nothing else.
3. **The page's names, the pictures' names and every copy's `.part` are reserved** (§1.5): a copy never stands where the page, a picture or another copy's part is written.
4. **The lowest occurrence id keeps the plain name, and the suffix goes before the extension** (§1.6): the choice is fixed by the record alone, and the copy still opens by its extension.
5. **Names are worked out from what is recorded, before a cluster's first copy** (§2), so resume trusts a copy at its name unread, as ADR-274 §2.4 has it.
6. **Names are cut to 100 code units and to 255 bytes with `.part`, and paths are not cut** (§3): a name that moved with the root would not be found on resume, and a name a common file system refuses would never be copied.
7. **A copy past 260 characters is written and counted, not refused** (§3), the count telling the operator what to change.
8. **A folder left behind is named where it is `documents/` and counted otherwise** (§4), a cluster's folder being named from a model's words.
9. **A link encodes every byte outside the unreserved set** (§5), so a space, `#` or `%` in a name leads to its copy.
10. **An image survivor is copied like every other** (§0), ADR-149 §4 and ADR-150 §4 being struck there.
11. **A name is made safe again after the cut** (§1.3): a cut can leave nothing or a device name, which the rules saw nowhere in the uncut name.
12. **What is held is a folder's path for each cluster and the names collisions changed** (§2), every other name worked out again from its survivor, and one partition's entry-picture HTML until its pages are written, so no source is asked a third time.

## Consequences

- **A reader of the tree finds each cluster's page, pictures and documents in one folder**, each document under the name it had in the archive.
- **A tree drawn before this record is redrawn in place at the next invocation that reaches it**: every survivor is copied again under its new name, its old copies stay in `documents/`, and the closing line says that folder can be deleted by hand. The old `<partition>/<cluster>.html` pages are files, and stay without a word.
- **A copy's path may pass 260 characters below a deep root**, and the survey counts how many do.
- **A copy's name holds none of the characters, device names or trailing dots and spaces Windows refuses** (§1.2), whatever the original was called on the system that holds it.
- **A folder put at the top of a named root, or in a partition folder, by anyone but the writer is counted as left behind** by the closing line.
- **What is held while the tree is drawn gains a folder's path for each cluster and the name of each copy a collision changed**, one cluster's names while its copies are made, and one partition's entry-picture HTML until its pages are written.
- **A redrawing's first line of the copies counts every survivor listed**, though its copies stand, and the line after the last counts them as already standing.
- **No run id moves** (§8).

## Alternatives refused

- **The occurrence id on every copy**, as ADR-274 §2.1 had it: the operator asked for the original's name, with a suffix only on a collision.
- **The suffix after the extension**, `report.pdf~42`: the copy would no longer open by its extension.
- **Comparing names as written, or with case on some systems**: two names one case apart would meet on Windows, where the tree may be carried.
- **A key upper-cased without being lower-cased first**, NFC(upper(NFC(name))): `θ.txt` and `ϴ.txt`, and `ß.txt` and `ẞ.txt`, would keep their plain names and be one file where case is folded, the second copy taken as standing and its link opening the first's bytes (§1.4).
- **The decomposed key alone**: `U+03B1 U+0345 U+0342 .pdf` and `U+03B1 U+03B9 U+0342 .pdf` key apart, form D sorting U+0345 after U+0342 in the first, yet NTFS upper-cases both unit by unit to one name, the second copy taken as standing and its link opening the first's bytes (§1.4).
- **A key composed before it is cased**, NFC(upper(lower(NFC(name)))): `ᾼ͂.pdf` (U+1FBC U+0342) and `ᾷ.pdf` (U+1FB3 U+0342) would keep their plain names, U+0345's `Ι` upper-cased before the perispomeni in one and after it in the other, and be one file on NTFS and on APFS's case-insensitive form, the second copy taken as standing and its link opening the first's bytes (§1.4).
- **Copies under their root-relative paths**, refused by ADR-274 for long paths and names a parser refuses: only the last element of the path is kept (§1.1).
- **Cutting a name by where the tree lies**: the name would move with the root or the working directory, and resume would not find a copy that stands (§3).
- **Refusing a copy whose path passes 260 characters**: the JDK writes it, and the operator is told by the count.
- **Reading the originals to name the copies**: a name is worked out from what is recorded (§2).
- **Deleting what an earlier drawing left** (ADR-103, ADR-276 §3), and **naming every folder left behind**, whose names come from a model's words (§4).
- **A table of copy names**: the tree stays the only record of a copy (ADR-274 §2.3), and a name is worked out again from fixed members.
- **Holding every copy's name until the manifest is written**: a collection as large as the survivors, where all but the renamed follow from the survivor alone (§2).
- **Counting before the first copy only the survivors whose copy does not stand**: it would work out every cluster's names twice, once before the copies and once at them (§3).

## What this does not decide

- **A page split into `index-2.html` and on** (#571), and **the pictures inlined into the page** (#560).
- **A program opening a copy past 260 characters** (§3).
- **A program opening a stemless name past 100 code units** (§1.6).
- **A file an earlier drawing left inside a folder this drawing wrote** (§4).
- **How the agent guard recognises a tree**, which [ADR-283](0283-the-private-paths-guard-reads-a-deliverable-tree-as-outside-the-allow-list-wherever-it-lies-by-its-marker.md) decides by the tree's marker and not by any name in it, so that it holds of this layout as of ADR-274's.
- **A file system that compares names by a fold other than NTFS's or APFS's case-insensitive form's** (§1.4), which may hold as one file two names the key keeps apart.
- **An NTFS volume that makes 8.3 short names**, as a Windows system drive does by default. It may give a copy with a long name the short name `NAME~n.EXT`, `n` from 1 to 4, which is also the form of a suffixed name (§1.6), and Windows resolves a short name as it does a long one. So where an earlier drawing did not make a suffixed copy, `Files.isRegularFile` at its name can find the other copy under its short name, and that copy is reported as already copied, its link opening the other copy's bytes. The suffix stays `~<occurrence id>`, as #570 settled it (§1.6).
