## Context

**How an invocation is shown today.** `vespera run` rewrites four HTML pages in the working directory every `vespera.progress-interval`, `progress.html` and its three tabs of detail, with `progress.json` beside them for the control panel (ADR-265 to ADR-269, ADR-344 §2), each carrying one script that reloads it, keeps the timeline's folds in its address, marks it stale and draws a hover over each chart (ADR-269 §3, ADR-324 §5, ADR-327). `vespera label` writes `progress.html` as a page of its own, at its start and its end (ADR-266 §3). `SystemPageOpener` opens the progress page, and the generation step the deliverable's index, in the system's browser: `rundll32` on Windows, `open` on macOS, `xdg-open` elsewhere, nothing where `CI` is set or, off Windows and macOS, where neither `DISPLAY` nor `WAYLAND_DISPLAY` is set (ADR-266 §2, ADR-274 §7), and nothing where `vespera.open-browser` is false (ADR-327 §5). The control panel's child runs with `CI=1` (ADR-278 §1). Every `vespera run` that starts the job writes `logs/invocation-account-<start>.txt`, its steps, runs, counts, progress lines and failures by type, built from an allow list that names no path (ADR-198, ADR-270). The jar started with no argument tries the window, and only the toolkit's own failure tells it there is no display (ADR-342 §2). The window draws the job's steps in the progress page's four legs from `Legs.ALL`, a copy of ADR-324 §1's table that `pipeline.TheControlPanelsLegsAreTheProgressPagesTest` holds to what `progress.html` draws, and that ADR-361 leaves to the record retiring the page to re-home (its *What this does not decide*).

**What else is written as text.** `effective-values.properties` (ADR-330), `next-invocation.properties` (ADR-294), `documents.csv`, `code.csv`, the website's `vespera-website.json` and `files.json`, and the Confluence rendering's `pages.json`, each for a reader of its own.

**The reports.** `Reports.ALL` names sixteen files (ADR-344 §6): the four progress pages, and twelve pages a step writes for the operator to read a value off, eleven through `ReportPage` (ADR-130) and the last through `deliverable`'s `Html`: `format-mix.html` (`ByteLevelReductionTasklet`), `extraction-failures.html` (`ReviewListListener`), `extraction-survivors.html` (`SurvivorListListener`), `confidence-distribution.html`, `document-frequency.html` and `word-count-distribution.html` (`ContentCensusTasklet`), `seed-corpus-comparison.html` (`SeedCorpusComparisonTasklet`), `translations.html` (`TranslationTasklet`), `cluster-sizes.html` (`ClusteringTasklet`), `relevance-labelling.html` (`RelevanceReportTasklet`, which writes it, and `RelevanceLabellingReport`, which draws it), `arrangement.html` (`ArrangementTasklet`), all of `pipeline`, and `cluster-page-sizes.html` (`ClusterPageSizes`, of `deliverable`). This record calls those twelve the **analysis reports**. No stage's version names `pipeline` or `deliverable` (`StageModules`). The window opens each in a tab of its own, in JavaFX's `WebView`, which `Cockpit` alone of the control panel's classes names (ADR-344 §6); `javafx-web` brings it with `javafx-media` and `jdk-jsobject`, which ADR-342's Context measured at 37,266,121 bytes of the jar built on Windows, WebKit writing `jfxwebkit.dll`, 96,460,800 bytes, into JavaFX's cache at the first report opened. The toolkit, its controls and its charts are `javafx-graphics`, `javafx-controls` and `javafx-base`, which hold no part of WebKit.

**What was measured.** On Windows 11 with OpenJDK 26.0.2.1, a probe outside the repository called `user32`'s `GetProcessWindowStation` and `GetUserObjectInformationW` with `UOI_FLAGS` through `java.lang.foreign`, run with `--enable-native-access=ALL-UNNAMED` from the desktop the operator is logged on at: the window station answered `WSF_VISIBLE` set, `kernel32`'s `ProcessIdToSessionId` answered 1, and the probe took 25 ms from its first line, linking included. A process with no visible window station was not run: that a service's station lacks `WSF_VISIBLE` is the system's documented rule, the flag .NET's `Environment.UserInteractive` reads. Nothing was run on macOS or Linux. Spring Boot 4.1.1's dependency management names `com.samskivert:jmustache` at 1.16, its last release; JMustache resolves a name against a `Map` by its keys, and against any other object by a method, a getter or a field of that name, through its `DefaultCollector`, which extends `BasicCollector`, and escapes HTML in `{{name}}` unless told not to.

## Decision

### 1. A display is present where a window can open

**`DisplayPresence`, a public class of `pipeline`, answers once per process whether a display is present, and why**, from the system the process runs on, `os.name` read as `HostSystem.named` reads it (ADR-323 §5), in lower case, macOS where it holds `mac` or `darwin`, else Windows where it starts with `windows`, else any other:

| System | Present where | `display.reason` |
| --- | --- | --- |
| macOS | CoreGraphics' `CGSessionCopyCurrentDictionary` answers a dictionary, which is released, rather than none, through `java.lang.foreign` | `window-server` or `no-window-server` |
| Windows | the process's window station, `GetProcessWindowStation`, carries `WSF_VISIBLE` in its `UOI_FLAGS`, read by `GetUserObjectInformationW` through `java.lang.foreign` | `visible-window-station` or `hidden-window-station` |
| any other | `DISPLAY` or `WAYLAND_DISPLAY` is set and not blank | `display-variable` or `no-display-variable` |
| any, started with `--headless` first | never | `headless` |
| any, where the native call throws or a library is not found | never | `not-answered` |

**It is asked once.** `EntryPoint` asks it before anything else where the jar is started with no argument (§2), before Spring has configured any logging, so a `not-answered` there is said in §2's line on standard error, with the exception's class name, and nowhere else. The command line asks it once its logging is configured, when its report is first written, the answer held for the invocation, and a `not-answered` there is one warning through `DisplayPresence`'s logger, `whether a display is present could not be asked: <exception class name>`, on the console and in `logs/vespera.log`. `--headless` first is handed to the command line by `EntryPoint` as the JVM's system property `vespera.headless`, which `EntryPoint` sets and `DisplayPresence` reads with `System.getProperty` and never through Spring's `Environment`, so that no relaxed binding reads it: `VESPERA_HEADLESS` in the environment and `vespera.headless` in `application-local.yaml` change nothing, and no file the jar ships names it. The command line's answer is then `headless` without asking the system. A `-Dvespera.headless` an operator types to the JVM says what `--headless` says, forcing none, which is the one thing the operator may force. `EntryPoint.chosen` stays a function of the arguments alone, `CONTROL_PANEL` for none; `main` asks the display after `chosen` says so. **A GPU plays no part**: no graphics card, driver or OpenGL is asked of. **The operator cannot force a display present**; `--headless` is the one override, and it forces none.

**The seams.** The Windows and macOS calls are each one method of an interface `DisplayPresence` is given, so that a test answers them on any system; `DisplayPresence.of(String osName, Map<String, String> environment, boolean headless, NativeDisplay windows, NativeDisplay mac)` decides, and `DisplayPresence.ofThisProcess()` reads the system's own. Surefire's and failsafe's runs are given `--enable-native-access=ALL-UNNAMED`, as the jar's manifest already gives it (ADR-342 §2).

### 3. The invocation report

**`report.json`, at the top of the working directory, is the invocation report**: one JSON file, the single source from which `report.html`, the window and any script or agent read how the invocation in hand, or the last to end, stands. It is written by `vespera run`, `vespera label` with or without `--auto`, and `vespera publish`, by each of them once picocli has parsed its arguments and the command runs, holding the working-directory lock (ADR-177), a refusal of the command's own after that included, a corpus root not there among them. An invocation refused before then writes none: before the lock, a working directory in use, not there or not a folder, so that it never overwrites the report of the invocation that holds it; a profile `ProfileShapeCheck` refuses, before the application context exists; and arguments picocli refuses, `run --bogus-option` among them. Its line on standard error is all it says.

**When it is written**, whole, into `report.json.part` and moved over `report.json` by `ReplacingMove` (ADR-223 §3), and drawn into `report.html` the same way after each write (§5):

- `vespera run`: once as the job starts, every `vespera.progress-interval` while it runs from the writing thread ADR-265 §2 gives the page, and once as it ends, under ADR-265 §2's lock, so no write of the running report lands over the last;
- `vespera label`: as it starts and as it ends;
- `vespera publish`: as it starts, after each destination ends, and as it ends;
- a refusal after the lock: once, with the refusal.

**A write that fails fails nothing**, as ADR-265 §4 has it: caught where it is made, one warning, `the report could not be written: <exception class name>`, until a write succeeds again, and the next write on time.

**What it holds, format 1.** Every instant is ISO 8601 in UTC with `Z`, to the millisecond; every duration is in whole seconds; every size in bytes; every count a JSON integer; a field with nothing to hold yet is `null`, never left out.

| Field | What it holds |
| --- | --- |
| `format` | `1`, the integer `InvocationReport.FORMAT` holds |
| `vespera` | the jar's version, as its manifest names it |
| `invocation` | `id`, the start in UTC as `yyyyMMdd'T'HHmmss'Z'` with `-2` and on for a second in the same second, which names the copy (§4); `pid`, the process's own, `ProcessHandle.current().pid()`; `command`, `run`, `label`, `label --auto` or `publish`; `started`, the instant the command begins to run, once picocli has parsed its arguments and the working-directory lock is held, read from the jar's clock to the millisecond, so that it is no earlier than the instant a window took before it started the process, and no earlier than the holder line's `started` less a second (§8); `ended`; `state`, `running` or `ended`; `outcome`, ADR-265 §1's `completed`, `failed` or `stopped` for `run`, ADR-266 §3's `recorded`, `refused` or `failed` for `label`, `delivered` or `stopped` for `publish`, `refused` for a refusal, `null` while running; `exitCode`, `null` while running; `writtenAt`; `interval`, the seconds between writes |

**What it never holds**: a document's text, title, opening or name read from its content, a cluster's label or title, a model's prose, a converter's message, a verdict's or a fault's stored reason or detail, and an exception's message. The paths it names are the folders the invocation was given, the files it wrote, and those the jar's own lines name: a refusal, a closing line or a publish's line, which may name a file of the operator's, a document's among them, or the Confluence site's host and space key, as they do on the console. **It is built from typed values** as ADR-198 §2 built the account: an enumeration, a step name, a count, an instant, a `Path`, and a line of the jar's own printed whole; no method of `InvocationReport` takes a `Throwable`'s message or a document's field.

**The format and its schema.** The schema is `docs/report/report.schema.json`, JSON Schema 2020-12, using only `type`, `properties`, `required`, `items`, `enum`, `const`, `additionalProperties` and `description`, every field described; its `format` is a `const`. **A change that removes, renames or changes the meaning or type of a field raises `format`** by one, in the same change as the schema; a field added is no break, and a reader ignores a field it does not know. **A reader refuses a `format` it does not know**: the window (§8), and the jar where it reads a report of its own kind (§9). The record of each number is its schema's history in the repository.

### 4. The copy kept per invocation

**Each write of `report.json` writes the same text to `logs/report-<invocation.id>.json`**, the same way, so a process killed partway leaves its last state there, as ADR-198 §8 had the account leave its progress lines. The `logs` folder is made where it is not there (ADR-270 §2). A copy is never deleted or rewritten by a later invocation. It replaces `invocation-account-<start>.txt`, which no invocation writes from this record's build on; the accounts already written stay where they lie. A `vespera.account-dir` still set costs ADR-270 §3's one warning, its words now `vespera.account-dir is no longer read, and the report's copy is written to <working directory, absolute>/logs`.

**What the account carried that the report does not**: every progress line in its order. The report keeps each step's last line, the samples behind the charts and the copy's last state; the whole run of lines stays in `logs/vespera.log`.

### 5. `report.html`, drawn from `report.json` through a template

**After each write of `report.json`, `ReportHtml` of `pipeline` draws `report.html` beside it**, through `.part` and `ReplacingMove`, from the text just written, read back, so the drawing is a function of `report.json` alone: the same `report.json` draws the same `report.html`. Nothing is served and nothing is opened.

**The engine is JMustache.** The pom gains, at compile scope, `com.samskivert:jmustache`, its version Spring Boot's dependency management gives, 1.16, under a comment naming this record. No `spring-boot-starter-mustache`. The compiler is built once per invocation:

- **its collector reads keys and nothing else**: a `Mustache.Collector` built on JMustache's `BasicCollector`, which resolves a name against a `Map`'s keys and walks a list, and never against an object by a method, a getter or a field, so `{{class}}`, `{{bytes}}` or any other name reaches no Java member;
- **its model is plain data**: `Map`, `List`, `String`, `Boolean`, `Long` and `Double` alone, made from the JSON read back and from §5's `drawn`; no lambda, no object of a class of the jar's;
- **it has no template loader**, so a partial, `{{> name}}`, though it compiles, since JMustache loads a partial only as it is drawn, throws at its first drawing, JMustache's failing loader's `UnsupportedOperationException`, which the trial drawing below meets;
- **`defaultValue("")`**, so a name the model does not hold draws nothing, and HTML escaping on, as JMustache ships it.

So a template reads the model and nothing else, and writes text: it cannot run code.

**The template's data model** is one map of two keys:

| Key | What it holds |
| --- | --- |
| `report` | `report.json`'s tree, as written, field for field |
| `drawn` | what a logic-free template cannot compute, derived from `report` alone by `ReportHtml`: `title`; `status`, ADR-269 §2's line and ADR-327 §2's sentence after the end; `writtenAt` and each step's times in the machine's zone; `refreshSeconds`, `invocation.interval` rounded up, at least 1; `tiles`, each `key`, `label`, `value`, `detail` and `hover` (ADR-268 §5, ADR-275); `timeline`, its `viewBox`, its axis's ticks, and each leg's and step's bar as `x` and `width` in ADR-324's 1,100 units, with its `title` and `hover`; `charts`, each chart's `viewBox`, `caption`, gridlines, each line's `points` as SVG's `x,y` pairs, `dash`, end label and latest value, every point's `title`, and its values as a `table` of `header` and `rows`; `steps`, `runs`, `gates`, `faults`, `refusals` and `analysisReports` as rows of formatted cells; `files`, each `role` in words, `path` and `href`, its `file:` address; `display` and `opened`, each in words |

`drawn` is the template's alone and is not written into `report.json`.

**The shipped template** is the resource `io/algernon/vespera/pipeline/report.html.mustache` in the jar. It draws one self-contained page: one `<style>`, no `<script>`, no `fetch`, no stylesheet, font or picture outside it, no `{{{ }}}`, and a `Content-Security-Policy` of `default-src 'none'; style-src 'unsafe-inline'; img-src data:` in its head, so it opens from disk in any browser. Its links to the analysis reports are their bare file names, which lie beside it.

**The operator's template.** `vespera.report.template`, an application property named in `application-local.yaml` or the environment and unset as shipped, names a template file by an absolute path, since the window's child runs in another current directory than the operator's shell (ADR-278 §1); a relative path is a template that cannot be used. It is read, compiled and drawn once on trial, over the report of the invocation's first write, as the invocation starts, so that a partial, or any name that throws as it is drawn, is met then. A path that is not absolute, a file that cannot be read, one that does not compile and one whose trial drawing throws are each one warning, `the report template <path> could not be used, so the jar's own draws report.html: <exception class name>`, and the jar's template draws every write of that invocation; a drawing that throws partway is the same warning and the same fall-back, for that write and the rest. `report.json`'s `template` says which drew it. It is no profile value and no preset: it enters no run (ADR-298), `effective-values.properties`, which holds no path, does not list it, and the window does not offer it, the child reading `application-local.yaml` as the command line does.

### 7. The console lines

**Every console line of the commands stays as it is, but for the two of the report.** As its first line, where ADR-266 §1 logs `Progress page: <path>`, each invocation that reaches that line logs, through the command's own logger at INFO:

```
Report: <absolute path of report.html>
```

and, as its last line, once its last write of the report is made and after its closing line, one line through the same logger, which this record calls the **report line**:

```
Report: <files clause>. Nothing was opened: <opened clause>.
```

| Part | Where | Its words |
| --- | --- | --- |
| files clause | the last write of all three made | `<report.json>, drawn as <report.html>` |
| | `report.json` not written | `not written to <report.json>: <exception class name>`, and nothing of `report.html`, which is drawn from it |
| | `report.json` written and `report.html` not drawn | `<report.json>, not drawn as <report.html>: <exception class name>` |

| opened clause | a display present | `a command opens no window, and the control panel's is the only one` |
| | no display | `there is no display here (<reason in words>)` |

Every report line starts `Report: `, and no other line the command prints after its first does. **The first line is logged where `Progress page: <path>` is today** (ADR-266 §1), past the last refusal of the start and before the first step, so an invocation refused after it holds the lock (§3) prints none: its refusal line, on standard error as today, is its closing line, and the report line follows it, the refusal being in the report it names. The rule that tells a closing line from a report line, for every reader and every test, is that **the closing line is the last line that does not start `Report: `**. Each path is absolute and in the system's form, as ADR-266 §1 writes one. **The closing line is the last line but one**: the operator reads the value to set next on it, the report line after it. `ExtractionHealthCheckListener` and the failure lines of stage 1 and stage 4a stay the closing lines they are. `TaskExecutorJobLauncher`'s and Hikari's lines stay off the console at INFO (ADR-281 §1), so nothing follows the report line.

### 8. The control panel

**The window reads `report.json`, and no `progress.json`.** `InvocationReportFile`, a class of the control panel built on its own `JsonReader`, replaces `ProgressFile`:

```java
public static final String FILE_NAME = "report.json";
public static final int FORMAT = 1;
public record Report(int format, Invocation invocation, List<Step> steps, List<Chart> charts, ...) {}
public static Report read(String json);   // IllegalArgumentException where it is not that JSON, or its format is not FORMAT
```

its records the fields §8 shows, by §3's names, and ADR-344 §2's `Step`, `Chart` and `Line` as they are. It reads the working directory's report every `vespera.progress-interval` as the presets give it, as the window reads `progress.json` today, while its child runs or a foreign holder line is held (ADR-278 §4), and once as the child ends, since the report's own `interval` cannot be known before its report is accepted; a file not there, unreadable or not that JSON leaves the window as it was, and one of another `format` leaves it so too, `outcome` saying *the report is of format `<N>`, which this window does not read*.

**A report is shown as the watched invocation's only where it is that invocation's.** Until the child's first write, `report.json` is the previous invocation's, with its closing line, faults, next value and legs; so every reading, live or last, is taken as the invocation's only where `invocation.pid` is the process the window watches, the child's `Process.pid()`, or, for an invocation the window did not start (ADR-278 §4), the `pid` of the holder line it read, and `invocation.started`, written to the millisecond (§3), is no earlier than the instant the window took before it called `ProcessBuilder.start()` for the child, or no earlier than the holder line's `started`, which is to the second, less a second, so that a pid the system gave again to a later process is not taken for it. A report that is not the watched invocation's is not drawn: the rows, the legs and the charts are drawn as before any report is read (ADR-344 §1, ADR-361 §5), and the Report tab's status line says *waiting for this invocation's report* while the child runs or the holder line is held. A child that has ended without any report of its own, as one refused before the lock, leaves the status line saying *this invocation wrote no report*, with how it ended from its last line of output that is not blank (ADR-278 §5), and the window reads no more for that child; reading starts again with the next child, or while a foreign holder line is held. A foreign holder's report is shown beside its holder line.

**What it shows natively**, drawn by JavaFX's controls from `InvocationReportFile.Report` and never by a `WebView`:

- the steps' bars and the three charts, as ADR-344 §1 and §2 draw them, from `steps` and `charts`, the steps in the four legs of [ADR-361](0361-the-cockpits-steps-fold-into-the-progress-pages-four-legs-and-its-copy-of-their-table-is-held-to-the-pages-by-a-test.md): `Legs.ALL`, the control panel's copy of ADR-324 §1's table, stays, since the window draws its rows and legs before any report is read, and `Legs.statesOf` and `Legs.openOf` read an `InvocationReportFile.Report` where they read a `ProgressFile.Progress`. **The copy stays held to the jar's**: `pipeline.TheControlPanelsLegsAreTheReportsTest`, which replaces `pipeline.TheControlPanelsLegsAreTheProgressPagesTest` in step 4, drives the job's listener as that test did and holds `Legs.ALL` to the `legs` and the `leg` of each step in the `report.json` the jar writes, and `Legs.statesOf` and `Legs.openOf`, read off that report's steps, to its legs' `state` and `open`, for the same six jobs, so that a leg or a rule changed in one place and not the other fails the build. The jar has one table of legs: in step 2 `LEGS` moves from `ProgressPage` to `InvocationReport`, package-visible, and `ProgressPage` reads it there, as it reads `STEPS_OF_A_STAGE`, so that the page and the report cannot differ while both are written; in step 11, when the page goes, it turns private;
- **a tab `live-report`, titled Report, first of the tabs pane** and not closable, holding the status line, the display and what was opened, the gates with their keys and the reports each is read off, the refusals, the faults by type, the closing line and the next value, each analysis report's headline numbers, and the files; a report's name opens that report's tab (§10), and the deliverable's index is handed to the system (ADR-344 §6's row for a file of a deliverable). `report.html`'s and `report.json`'s paths are shown as text, never opened;
- **stale**, beside the status line, where `writtenAt` is more than three `interval`s behind the window's clock while the report's `state` is `running`, as ADR-267 §5 had the script mark it.

### 9. The analysis reports write what their pages show as JSON

**The reports given JSON are the twelve analysis reports.** The four progress pages' data is `report.json`'s (§3, §6), and they write no JSON of their own.

**Each of the twelve writes `<name>.json` beside `<name>.html`**, its name the page's with `.json` for `.html`, by the class that writes the page, at the moment it writes it, through `.part` and `ReplacingMove`, so that no class holds more for it than it holds for the page (ADR-220): where the page streams its rows, as the review list (`ReviewListListener`) and the survivor list (`SurvivorListListener`) do, the JSON is written a row at a time beside it; where the page is drawn from one value, as the format mix is (`ByteLevelReductionTasklet`, whose page is written whole and not through `.part` today), the JSON is written whole from the same value. **The JSON is moved into place before the page is written**, and, for a streamed page, whose two `.part` files are written in one pass, before the page is moved. A JSON that cannot be written or moved is handled as the class handles its page's failure: `ByteLevelReductionTasklet` throws and fails the step, as a page that cannot be written does, and `ReviewListListener` and `SurvivorListListener` log one error naming the JSON and go on; in each the page is then not written, so the earlier JSON and the earlier page stay one pair, each with its own `writtenAt`. A page that cannot be written after its JSON is moved leaves the new JSON beside the earlier page, which the window shows by `writtenAt` and `written-<name>`, and is handled as that class handles it today. The eleven of `pipeline` share one writer of the shape; `ClusterPageSizes`, of `deliverable`, which names nothing of `pipeline`, writes its own in the same shape, and each schema, held by test, is what makes the twelve one. The twelve share one shape:

| Field | What it holds |
| --- | --- |
| `format` | the report's own, from 1 |

## Consequences

- One file says how an invocation stands, for a person, a script, CI and an agent alike, and every view of it, the page, the window and the console's last line, is drawn from it.
- No command opens a browser or a window on any machine, so a run on a machine without a display, or over a remote shell, tries nothing graphical but ADR-323 §5's start of Docker Desktop where the engine does not answer; the operator opens `report.html` from its path, or reads the window.
- A start of the jar with no argument on a machine with no display loads no JavaFX class and answers as the command line in the time the check takes.
- The operator who reads the last line for the value to set next reads the line before it.
- `report.html` reloads in an open tab as the progress page did, with no script, so a leg folded by hand opens again at each reload and a chart shows a point's value only by the point's own title.
- The account's place in `logs/` holds a JSON copy per invocation, `vespera label`'s and `vespera publish`'s among them, naming paths it did not name before and holding each step's last progress line where it held them all.
- The jar gains JMustache and loses `javafx-web`, `javafx-media` and `jdk-jsobject`, about 37.3 MB where it is built on Windows, and the first report opened on a machine writes no WebKit library.
- The window keeps its copy of the legs' table, and a test of the jar's package holds it, with the rules for a leg's state and its fold, to the legs the report holds.
- Twelve JSON files lie beside the analysis reports, the lists among them as long as their pages; the window draws each report itself, and the page in the working directory is for opening outside Vespera.
- No run id moves.

## Known limits

- **The macOS and Linux answers were not run**: the macOS call and the variables are the systems' documented rules; on Linux a `DISPLAY` naming a server that does not answer is a display present, and the toolkit's failure is then the answer (§2).
- **A Windows process whose station is not visible was not run**; its answer is the system's documented flag.
- **A fold of the timeline does not outlive a reload** of `report.html`, nor does a hover's crosshair exist.
- **A replaced template is held only to reading the model**: what it draws, whether it carries a script, and whether it escapes what it writes with `{{{ }}}` are the operator's.
- **The report's staleness is shown by the window alone**; a browser shows the time written and the interval, and a reader judges.
- **A report's native view and its page are two drawings of one file's values**: the numbers and rows agree, held by test, and how each looks does not. A page's prose a section's `text` does not carry is the page's alone.
- **A class that builds a list headed `open` and hands it to another class to run**, as `HostSystem` does for `SidecarStarter`, is not seen by the test of §2; only a reader of the code sees it.
- **A wall clock stepped back between the window's instant and the child's `started`** leaves the child's report unshown, the status line saying *waiting for this invocation's report* while the child runs, since the guard compares two readings of one clock taken a moment apart.
- **An analysis page carries no write time**, so outside Vespera a new JSON beside an earlier page, which §9's failure of a page's write can leave, cannot be told from a pair: only the window shows `writtenAt`.
- **A long list is read whole into the window's memory as its tab opens**: the survivor list of a large corpus is its page's rows, in JSON.
- **The copy per invocation is rewritten at each write**, so `logs/` holds one file per invocation of a size the report's, about the samples' 256 rows at most.

## Alternatives refused

- **A display read from a GPU, a graphics driver or OpenGL.** A window needs a desktop to draw on, not an accelerator; a machine with a card and no one logged on has none.
- **The toolkit's own failure as the only answer** (ADR-342 §2). It loads JavaFX on a machine that cannot show it, and says nothing a command could write in its report.
- **An option forcing a display present.** The operator gave `--headless` alone, forcing none; a display forced where none is would try what cannot succeed.
- **`SESSIONNAME` on Windows.** It is set by the logon for the desktop it starts, and absent over a remote shell or a service, but it is a variable any parent may set or drop; the window station is the system's own answer.
- **Each command opening `report.html` where a display is present.** The operator made the window the only window.
- **XML, or several files.** The operator chose one JSON file, which Jackson writes and every reader parses.
- **`report.html` served, or drawing itself from `report.json` with a script.** A `file:` page cannot read another file in the browsers an operator uses (ADR-327's Context), and a server is a program the invocation would have to keep.
- **The template's model as `report.json` alone.** Mustache computes nothing, so a chart's coordinates and a time in the machine's zone would be beyond any template; `drawn` derives them from the report and nothing else.
- **JMustache's default collector.** It resolves a name by reflection on any object in the model, so a replaced template could reach a Java member; the keys alone are what a logic-free template needs.
- **FreeMarker, Thymeleaf and JTE.** Each lets a template reach code: FreeMarker's `?new`, Thymeleaf's expressions, JTE's templates compiled to classes. **Pebble** is the named step up if a template later needs logic, and is not taken now, its filters and functions being more than drawing from a model needs.
- **The progress page kept beside `report.html`.** Two drawings of one invocation drift, and the operator replaced it.
- **The invocation account kept beside the copy.** Two files per invocation for one hosted reader; the copy is the account's successor.
- **The progress lines' history in the report.** Rewritten every interval, the report would grow with the invocation; `vespera.log` keeps every line.
- **The analysis reports' JSON holding their numbers alone.** A native view drawn from it would show no row of a list, no file to convert again and no cluster to approve, and the page would stay the one place to read them.
- **A shape of its own for each report's JSON.** Twelve shapes are twelve views; one shape of headline, sections, charts and tables is one view, each report's schema naming its parts.
- **`report.html`, or an analysis report, opened in a tab of the window's `WebView`.** The operator wanted every report drawn natively, and `javafx-web` out of the jar.
- **A `WebView` kept for the pages, the native views beside them.** Two drawings in one window, and 37 MB of WebKit for the second.
- **A new last line replacing the closing line.** The operator kept the console's lines; the closing line stays whole, before the report line.

## What this does not decide

- **Whether `next-invocation.properties` and `effective-values.properties` fold into the report.** Both stay the control panel's inputs (ADR-294, ADR-330); the report's `next` is written from the same value as the first.
- **Each analysis report drawn from its JSON through a template of its own** (§9).
- **A retention rule for the copies in `logs/`**, as ADR-198 left one for the accounts.
- **Whether `vespera serve` writes a report.** It holds no lock and opens no database (ADR-333 §8).
- **The words of the window's Report tab** beyond what §8 says it shows, and the shipped template's look beyond §6.
