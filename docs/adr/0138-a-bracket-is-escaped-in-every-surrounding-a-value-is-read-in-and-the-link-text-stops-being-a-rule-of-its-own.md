# ADR-138 — A bracket is escaped in every surrounding a value is read in, and the link text stops being a rule of its own

- **Date**: 2026-09-21
- **Status**: accepted
- **Amends**: [ADR-136](0136-the-angle-bracket-and-the-ampersand-are-backslash-escaped-and-the-heading-becomes-a-fourth-surrounding.md) — **two sentences, both false, and §7 below states what each is replaced by**: its Decision §4's *"A heading carries only `onOneLine` today because it has no pipe and no brackets to guard"*, whose pipe half is true and whose bracket half is not; and its Consequences' *"`onOneLine`'s callers divide"*, which describes the opposite of what that change did. Everything else in ADR-136 stands: `<` and `&` are backslash-escaped rather than entity-encoded, the backslash is escaped first, the heading is a surrounding with a rule of its own, the CSV is untouched, and the entity-shaped run is closed as a consequence. **Its §4's conclusion also stands** — a heading does not borrow the cell's rule — and only the premise it was argued from moves.
- **Rests on**: [`docs/research/deliverable-markdown-rendering.md`](../research/deliverable-markdown-rendering.md) **§9**, measured on 2026-09-21 across `markdown-it` 15.0.2 (both `html` settings), `marked` 18.0.13, the `commonmark` 0.31.2 reference (both `safe` settings) and GitHub's live `POST /markdown` in both modes — seven configurations, every fixture generated by running a writer and read back from the file it wrote. And on [ADR-134](0134-a-line-break-in-a-value-is-folded-and-three-escaping-rules-stand-because-there-are-three-surroundings.md), whose rule about surroundings and whose composition argument this record applies rather than contradicts; [ADR-137](0137-a-destinations-ampersand-is-percent-encoded-and-the-destination-is-a-fifth-surrounding.md) §4, which is what keeps the count from going vacuous here; [ADR-103](0103-the-deliverable-is-a-markdown-tree-in-the-working-directory-one-tree-per-run-id.md), the no-network claim the image case contradicts; [ADR-106](0106-a-cluster-gets-a-derived-label-from-6a-and-a-generated-title-from-6b.md), which says where these values come from; and [ADR-130](0130-one-report-page-module-owns-the-skeleton-styling-escaping-and-tables.md), whose rule against a second copy of one rule is what §3 below obeys.
- **Settles** [#258](https://github.com/algernon28/vespera/issues/258).

## Context

`Deliverable` escapes `[` and `]` in exactly one place: where it is itself composing a link. `asLinkText` writes them for the index's first column where the row carries a link, and `escapeLinkText` for a membership entry, both under ADR-134, and both for the same stated reason — an unescaped `]` closes the link the tool is building before the name has finished.

Two positions compose no link of their own, and neither escapes a bracket: an ATX heading (`inAHeading`) and a plain table cell (`inACell`). A value with both brackets live reaches them.

**That is enough for a value to compose a link of its own.** CommonMark parses an ATX heading's raw content as inlines ([§4.2](https://spec.commonmark.org/0.31.2/#atx-headings)), and a GFM table cell's content likewise, so a heading is an inline context in every renderer there is. Measured (§9c), with every fixture emitted by the shipped writer and read back off disk:

- `## seeds/[click me](evil.md) report.docx` renders `<h2>seeds/<a href="evil.md">click me</a> report.docx</h2>` in **seven configurations of seven**;
- `# Survey ![shot](https://example.com/x.png) 2019` renders an `<img>` in all seven, and the same value in the index's third column does the same;
- `| [click me](evil.md) report |` is a live link in the cell, in all seven.

None of it is renderer-specific and none of it is the table extension's doing: the `commonmark` reference has no tables at all, and the link and the image form in the paragraph a row falls back to exactly as they do in the four configurations that build the table.

### Where the values come from, which is why this is not academic

`inAHeading` is applied at `Deliverable.java:336` to a cluster's generated title, falling back to its derived label, and at `:217` to a seed's path. `inACell` carries the same two values into the index. ADR-134 established what each can hold and its phrase for the first is *"unbounded text under no filesystem constraint whatever"* — the title is what the generation model answered. The label is a document's own Docling title (ADR-106), and where that falls back to a filename stem, NTFS permits `[`, `]`, `(`, `)` and `!` in a name, so `[click me](evil.md) report.docx` is a file a walk can really record.

### The behaviour is older than the ticket, and one sentence of the record is not

ADR-134 guarded the bracket exactly where a link is formed. On what it then knew that was coherent, and nothing regressed afterwards.

What ADR-136 did was different in kind. Justifying why the heading gets a rule of its own rather than borrowing the cell's, its §4 opens *"A heading carries only `onOneLine` today because it has no pipe and no brackets to guard."* The pipe half is true and is the whole of what the paragraph goes on to argue from. The bracket half is false, and it converted an unguarded position into a position recorded as needing no guard — which is why this is a decision with an amendment attached rather than a four-line patch.

## Decision

### 1. `[` and `]` are escaped in a heading and in a cell, unconditionally

A value written into an ATX heading or a table cell has `[` written as `\[` and `]` as `\]`, on top of what ADR-134 and ADR-136 already write there. So `inAHeading` folds and escapes `\`, `<`, `&`, `[`, `]`; `inACell` does the same and then the pipe.

**The cost is real and is payable here, which is the part that had to be established rather than assumed.** ADR-134's standing rule is that a value is escaped only against the structure it actually lands in, and ADR-136 priced the plain-text reader's view explicitly — *"a plain-text reader sees two more backslashes"*. This makes it four. What makes them payable is that the character **is** structural in these two surroundings, measured in all seven configurations, which is exactly the test ADR-134 sets. It is the same trade those two records took, applied to a character they had wrongly concluded was inert here, and not a new kind of cost: `\|`, `\[`, `\]`, `\\`, `\<` and `\&` are already written into these same values elsewhere in the same file, and a reader of the raw `.md` is already looking at that list.

**And the escape is not what this costs the page.** Escaped, every word of the value survives into the heading's rendered text; unescaped, it does not (§2 below).

### 2. The image case is a different harm from the link case, and ADR-103 is what it contradicts

A live link is a wrong link: the reader clicks a name and arrives somewhere the archive never named. That is bad and it is visible.

A live image is not that. GitHub rewrites the `src` through its image proxy in both modes and serves the resource from its own origin — measured (§9e), the emitted element carries `src="https://camo.githubusercontent.com/…/68747470733a2f2f6578616d706c652e636f6d2f782e706e67"`, whose second path segment is `https://example.com/x.png` hex-encoded, beside a `data-canonical-src` naming the original. The four local libraries emit the author's `src` unchanged for a browser to fetch directly. Either way, **opening the page makes a request to a host named by a value out of the archive or out of a model's answer**, and ADR-103 is the record that says this tree resolves every link with no database, no ledger and no network. The two harms are closed by the same escape in the heading and in the plain cell, and they are not the same harm, and a later reader weighing the plain-text cost against the benefit should be weighing both. **The image harm is not closed in every position, and the escape is not what leaves one open**: in the index's linked first column, whose bytes this record does not change, `marked` alone reads the escaped `!\[shot\](…)` as an `<img>` and a page opened in it still fetches the host-named image (§9f, §9g) — that is [#261](https://github.com/algernon28/vespera/issues/261)'s shape rather than this one's, and it means ADR-103's no-network claim is restored in six configurations of seven and left **residual in `marked`** rather than restored everywhere. This record measures that and deliberately decides nothing about it; the Consequences below say why.

**There is a third effect, and it is the one ADR-136 was written to close.** An image's alt text is an attribute, not text content, so the word leaves the heading. Measured on GitHub (§9d), `# Survey ![shot](https://example.com/x.png) 2019` slugs to `survey--2019` and escaped it slugs to `survey-shothttpsexamplecomxpng-2019`. Two hyphens are all that is left of `shot`, and nothing anywhere says a word was removed. That is ADR-136 §3's silent-deletion failure arriving by a second route, in the same position, four sentences away from the assertion that the position was safe.

### 3. `asLinkText` stops escaping the bracket, because `inACell` now does it

`asLinkText` is `inACell` followed by its own `[` and `]` replacements. Once the cell rule inserts those escapes, the rule built on top escapes them a second time, and ADR-134's composition argument — a rule that inserts its own escape character merges with an escape already present — reaches a rule it was not written about.

This is measured rather than reasoned (§9f). A writer that adds the bracket to the cell rule and leaves `asLinkText` alone emits `[Survey !\\[shot\\](…) 2019](…)`, where `\\[` is an escaped backslash followed by a **live** `[`, and **six of seven configurations fail to form the link at all**. What they form instead is not an autolink, and naming it one undersells it: the live `[` opens a second bracket, `shot\\]` closes it, `(https://example.com/x.png)` completes it, and the cell renders as `[Survey !\<a href="https://example.com/x.png">shot\</a> 2019](…md)` — a CommonMark **inline link**, anchor text `shot\`, destination the host the value named, with the outer `[` deactivated by the no-links-inside-links rule and printing as literal text beside its own destination. So the naive shape does not merely lose the index's only navigation: **it emits a live link to a host named by the archive or by a model's answer, which is this record's own defect reappearing inside the fix for it.** `marked` alone still forms the intended link. That strengthens the conclusion rather than moving it — the shape is refused either way — but a later reader weighing the plain-text cost against the benefit should be weighing the right harm.

So `asLinkText` becomes `inACell(text)` and nothing else. What that is, stated plainly: **the link inside a cell stops being a rule and becomes a call site.** It never was a surrounding of its own in ADR-137's enumeration — it is a cell that happens to carry a link — and what it needed beyond the cell is now what the cell needs. Leaving the two replacements in place once the cell has them would be ADR-130's defect exactly: a second copy of one rule, in one class, free to drift.

`escapeLinkText` is untouched. A membership entry is its own surrounding, it already escapes both brackets, and nothing about it is composed out of `inACell`.

**One sentence of ADR-134 becomes an illustration of code that no longer exists, and it is deliberately not amended.** Its *"The load-bearing ground is composition"* paragraph reads "`inACell` *inserts* backslashes, and `asLinkText` inserts more on top of them", and after this change `asLinkText` inserts nothing on top of anything. That sentence is left as written: it was true when written, and it is a statement about this project's own code at that date rather than about the world — which is the distinction that made ADR-136 §4's claim about what a heading can carry amendable in §7 below and makes this not. It is noted here only so a reader tracing that sentence forward does not trip over it. The illustration is historical; the argument it illustrates is exactly what this section applies.

### 4. The narrower option is refused: the escape is unconditional, not conditional on what follows

The option is to escape a bracket only where what follows it would actually close or complete a link — cheaper for a plain-text reader, because an ordinary `Report [2019].pdf` would keep its brackets bare. It is refused on three grounds.

**ADR-134 already refused per-value rules, and this reaches that refusal.** Its reason is that a rule applied per value is one more place for a page to silently become a different page, and it declined to invent one even for the blank-line case it names as a genuine residual. A conditional bracket rule is that shape: the same value is escaped on one page and not on another, and the difference is decided by a predicate rather than by the position.

**The predicate is the link grammar, and owning a second implementation of it is the cost.** What closes a link is not `](` — it is CommonMark's inline link, collapsed and shortcut reference links, link labels with their own nested brackets, images, and a reference definition that may sit anywhere in the same value. To be right the predicate has to parse what a renderer parses. ADR-134's whole architecture is rules that guard a **grammar** without implementing one, and this would be the first that did.

**And it buys nothing the unconditional rule does not.** `replace` is already conditional in effect: a value carrying no bracket is untouched, which is ADR-134's own consequence, and the values that do carry one are precisely the ones a reader most needs to see whole.

### 5. The division of rules survives, and ADR-137 §4 is why it is not vacuous

The ticket's real question: if all four Markdown text positions escape the same set except the pipe, is ADR-134's division into surroundings still carrying anything, or is the honest record one rule with one pipe-shaped exception?

It survives, and not on ADR-134's own ground. That record argued the division from how differently the rules would behave if merged, and after this change the three Markdown text rules differ by exactly two facts — the cell escapes a pipe and the other two do not; the heading and the cell fold and the membership entry does not. That is thin, and an argument resting on how much the rules differ would be nearly spent.

**ADR-137 §4 states the ground that is not spent**: *what a surrounding answers to decides the form its rule takes, never whether it is one.* A surrounding is a position a value this tool did not compose is written into, which has a grammar of its own; it is one because it has one, not because its rule came out looking unlike its neighbours'. Read that way the five stand unchanged and the count keeps its practical value, which is a checklist: the next character found hazardous has five positions to be asked about, and three of the five will answer differently from the Markdown text positions — the CSV answers to a parser and doubles a quote, the destination answers to a resolver and percent-encodes, and this record adds a third fact of the same kind, that **two of the three text positions converging on one escape set is a result, not a merger.**

That the sets converge is worth stating rather than hiding, because it is what a later reader will notice first. Here is the whole of it, after this record:

| Surrounding | Rule | Folds | Escapes |
|---|---|---|---|
| A table cell | `inACell` | yes | `\` `<` `&` `[` `]` `\|` |
| An ATX heading | `inAHeading` | yes | `\` `<` `&` `[` `]` |
| A membership entry | `escapeLinkText` | no | `\` `<` `&` `[` `]` |
| The CSV manifest | `quoted` | no | RFC 4180 quoting |
| A link destination | `relativeDestination` | no | URI quoting, plus `%28` `%29` `%26` |

**The one thing that would collapse the division is a merge, and it is still refused for ADR-134's reason.** Give the heading the pipe and a plain-text reader gets `\|` for a hazard that does not exist on a line beginning with `#`. Give the membership entry the fold and a path with a run of spaces is shown as a path the archive does not hold. Give either to the CSV and a consumer loading it into a table gets literal backslashes in the column that has to name the document. The rules are as close as they are because three positions genuinely answer to one reader; they are not one rule because three positions genuinely have three grammars.

### 6. The CSV and the destination are untouched, for the reasons already recorded

`quoted` gains nothing: ADR-136 §5's argument carries over without a word changed, and a backslash in a manifest column is data rather than an escape, so `Report [2019].pdf` reaches a consumer as the archive spells it.

`relativeDestination` gains nothing either, and for a reason worth stating because it is not the same one. `java.net.URI`'s path quoting already encodes `[` and `]` to `%5B` and `%5D` (§8b), so a bracket never reaches a destination unencoded. The fifth surrounding is guarded here by an encoding applied for an unrelated reason, which is the same accident §8b records defusing the numeric character reference, and a later reader removing or replacing that encoder needs to know it is load-bearing twice over.

### 7. The two false sentences of ADR-136, and what they are replaced by

`docs/adr/README.md` reopens a record only by a later record, so ADR-136's file is not edited and both corrections are made here.

**Its Decision §4 opens** *"A heading carries only `onOneLine` today because it has no pipe and no brackets to guard."* **Read instead**: *a heading carries only `onOneLine` today, and while it has no pipe to guard, it has two brackets that were never noticed — a link and an image both form in an ATX heading in every renderer measured (§9).* The rest of that section is unaffected: the conclusion it argues, that a heading gets its own rule rather than borrowing the cell's, rests on the pipe half alone and stands. The brackets do not make a heading a cell; they make it a position that shares one more character class with one, which is exactly the shape ADR-136 §2 already names and answers.

**Its Consequences paragraph opens** *"`onOneLine`'s callers divide."* **Read instead**: *`onOneLine`'s callers converge.* It has exactly two, `inAHeading` and `inACell`; both are escaping rules, both reach a renderer, and before that change the two did different things with a value — one folded and escaped, the other only folded. Afterwards both fold and escape, and after this record they escape the same set but for the pipe. The sentence's second half — *"Anywhere `onOneLine` is called on a value that does not reach a renderer, nothing changes"* — describes a caller that does not exist, and the accurate form of the observation is that there is no such call site to reason about.

**One javadoc repeats the first of these and is `spec-implementer`'s to correct**, not this record's: `Deliverable.java:696` restates *"neither is structural on a line that begins with `#`"* of the pipe **and** the brackets, and it must say it of the pipe alone. Every other javadoc on `inAHeading`, `inACell` and `asLinkText` moves with the code.

## Consequences

**A plain-text reader sees two more backslashes, in two more positions.** ADR-103 makes reading the raw `.md` a supported way to read the tree, so the cost is real, and it is the fourth time this family of records has taken it. What bounds it is that the reader of a value carrying a bracket is the reader this most helps: unescaped, that reader is looking at a name whose rendered form is missing a word or is a link to somewhere else, and after this the raw file and the rendered page say the same thing.

**One rule disappears, and it is not a surrounding that lost one.** `asLinkText` becomes a call to `inACell`. Five surroundings stand and five rules stand; what went was an appendage that had become a second copy. ADR-130's premise now holds against the form it replaced, which is the first time that record's remedy has applied inside `Deliverable` rather than been distinguished from it.

**The production change is owed and is not made here.** `inAHeading` and `inACell` each gain two replacements, `asLinkText` loses two, and one javadoc sentence is corrected per §7. No `src/main` file is edited by this record, and the tests that pin the decision are red until that change lands.

**A heading whose value is a bare URL is still autolinked, and that is left alone.** Measured (§9f), `marked` and GitHub in both modes linkify a bare `https://` run inside a heading whether or not a bracket stands beside it — the GFM autolink extension, acting on the URL itself. It names the host the value named, adds no image and removes no word, so nothing here is a hazard of the kind this record closes. Escaping a value's colon or slash to defeat it would corrupt every path the tree writes into a heading, which is most of them.

**`marked` forms an image inside escaped link text, and this record does not decide it.** Measured (§9g): `!\[shot\](…)` in the index's linked first column is an `<img>` in `marked` and a literal `![shot](…)` in the other six. That is true of the shipped writer today, is neither caused nor closed by anything above, and the source is conforming — CommonMark makes `\[` a literal `[`. It is the shape of [#261](https://github.com/algernon28/vespera/issues/261): one renderer diverging from the specification the other six implement, and whether this project writes a defensive escape against that is the question that ticket asks and this one deliberately does not answer.

**What stays open is what every record in this family has carried**: which renderers an operator actually opens the tree with. VS Code's preview, IntelliJ's, Obsidian and github.com in a browser are unmeasured as applications, and everything above rests on four libraries and one HTTP API. The decision does not have to choose between them — the form it adopts is correct in all seven configurations measured, and the form it replaces is wrong in all seven.
