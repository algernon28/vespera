# Profile tab: operator texts, consolidated

## Rules

Decided by the operator on 2026-11-08.

- **Row** shows:
  - the title;
  - a description of at most two short sentences: what the value does to the result, and which report (opened from the link under the row) helps choose it;
  - a cost line: one short sentence saying what a change redoes and what is kept;
  - only where they apply, at most one line each for three warnings: **approval** (a grouping you approved must be approved again), **answers** (press Record my answers first, or unsaved answers in relevance-labels.yaml are lost, or the old answers file is refused), **new sample** (Vespera picks new documents for you to judge in relevance-labels.yaml).
- **No time estimates** anywhere.
- **Tooltip** (on the title) holds the key name, edge cases (empty, 0, 1, fractions, kinds of file not affected), units and ranges, and anything else needed for accuracy. It may be longer, but stays plain.
- Provenance is also in the tooltip (already decided; not covered here).

## Cost-line template

One sentence, by the earliest work a change redoes:

- **none:** "Changing it redoes no work; it takes effect the next time you press Publish."
- **sorting:** "Changing it redoes everything from sorting your files to writing the pages; text already read out of your files is kept."
- **reading:** "Changing it redoes everything after reading the text out of your files; the text already read is kept."
- **repeats:** "Changing it redoes the search for documents that say the same thing, the groups and the pages; your files are not read again."
- **seed:** "Changing it redoes everything from reading your seed documents to writing the pages; your other files are not read again."
- **closeness:** "Changing it redoes the measuring of closeness, the grouping and the writing of the pages; your files are not read again."
- **writing:** "Changing it redoes only the writing of the pages; everything before it is kept."

- **Approval** (approvalCloses): "Approval: a grouping you approved must be approved again in the Approved grouping row."

## Tooltips

- **seedFolder:** seedFolder. The full path to one folder, for example D:\archive\exemplars. Put in it a handful of documents (the seed documents) you know are the kind you want kept; nothing else tells Vespera what matters to you. Vespera never changes, moves or deletes anything in this folder. If it is empty or not set, Vespera has nothing to compare your documents against, so it cannot pick which ones to keep. Documents left out are only missing from the pages, never deleted. A grouping is how Vespera puts similar documents together; if you approved one, a change here asks you to approve it again. After a change, the old relevance-labels.yaml is refused. If a seed document cannot be read because of the file itself, Vespera does not try it again; only crashes and timeouts of the reader are retried.
- **degenerateOutputConfidenceFloor:** Key: degenerateOutputConfidenceFloor. A number from 0 to 1 (for example 0.5). When Vespera reads text out of a PDF or a scan, it gives each page of that file a quality mark from 0 to 1; the file's mark is the average over the file's own pages. Bands: below 0.5 poor, 0.5 to 0.8 fair, 0.8 to 0.9 good, 0.9 and above excellent. A file whose mark is below this number is left out: it is not in relevance-labels.yaml and not used in the pages in the Output folder. Nothing is deleted from your folders. Empty: no file is left out for its mark. 0: nothing is left out either. 1: every PDF and scan short of a perfect mark is left out. Word and plain-text files get no mark, so this number never leaves them out. No report names the files left out. confidence-distribution.html counts only the files kept in the last run; to see every PDF and scan, empty this row, run again, then open it. Files whose reading failed have no mark and are not counted there; a file that failed because of the file itself is never tried again, only reader crashes and timeouts are retried.
- **degenerateOutputWordFloor:** Setting: degenerateOutputWordFloor. Write a whole number, 0 or more. The panel refuses a fraction, a negative number or text and keeps the old value; if one is typed by hand into profile.yaml, Vespera treats it as no limit. Empty or 0: no file is left out for having too few words. 1 behaves like 0, because a file with no letters or digits is always left out. Words are the pieces of text between spaces; numbers and page headers and footers count. Every kind of file (Word, PDF, spreadsheet and others) uses the same number. Your seed documents are never held to it. Nothing is deleted from your folders. Files already set aside as code, logs or byte-for-byte copies stay set aside whatever this number is. The word-count report shows, for each kind of file, how many files a limit of 2 to 10, 20, 50 or 100 words would leave out.
- **boilerplateDocumentFrequencyFloor:** Key: boilerplateDocumentFrequencyFloor. When Vespera finds documents that say the same thing, it keeps only one of them; this value stops a shared letterhead or disclaimer from making documents look alike. It is a share from 0 to 1 of the documents whose text Vespera read, the number shown as N at the top of document-frequency.html: 0.4 means 40%. A run of five words in a row counts as repeated text when it appears in at least this share of those documents. Set too high, documents that share only a letterhead can look alike, and one of them is left out. Set too low, real shared content is ignored, so true repeats stay in. Left empty, Vespera stops before this check and writes no documentation pages. document-frequency.html shows counts only, never your text, and its rows run from the lowest share at the top. If you enter the share shown on a row of document-frequency.html, the passages on that row and on every row below it count as repeated text; passages on the rows above do not. Copy the value in the row's "Share of documents" column exactly as shown. Or divide the row's "Fewest documents" by "N", and write the result in full or with at least as many decimal places as N has digits. Never round the result up: for passages found in 2 of 3 documents, 0.67 is above 2/3 and misses them, so write 0.666 or less. The report is rewritten each time Vespera reads your documents' text.
- **embeddingModel:** Key: embeddingModel. The name of an AI model on this computer, as known to the program that runs AI models here (set up with Vespera). Vespera comes with hf.co/Qwen/Qwen3-Embedding-8B-GGUF:Q4_K_M. This is not the writing model. Left empty, Vespera uses the model shown in the 'In use' line. If the named model is not on this computer, it is downloaded before the measuring starts (the one Vespera comes with is 4.7 GB). Each model scores closeness differently for the same documents, so after a change check Relevance cut-off and Translation match, two other rows on this tab, again: the same values can keep more or fewer documents. With Approved grouping set to auto, nothing waits for your approval. The new set to judge is about sixty documents; answers you already saved with Record my answers are kept. All kinds of file are affected alike. The reading of text out of your files is not redone, and a file whose reading failed because of the file itself is still not read again; only reader crashes and timeouts are retried.
- **relevanceScoreFloor:** Key: relevanceScoreFloor. A closeness number: how close a document is to your seed documents, measured by the Comparing model. Pick a value between the lowest and highest closeness shown in relevance-labelling.html. The scale is not fixed: it depends on the Comparing model and on how many of the closest seed documents Vespera counts for each document (that count is not a row on this tab). Empty: nothing is left out. A document below the number is only left out of the pages; your file is never deleted or moved. The cut-off is used only when every relevant / not relevant answer you saved was given under the current Comparing model, or when you saved none. Otherwise it is ignored, and Vespera says so in its log and in a note in relevance-labelling.html. If you change the Comparing model, mark the new documents, press Record my answers, then set this number again. Vespera may fill this number in itself from your answers, choosing the highest number that leaves out no document you marked relevant; a number you typed yourself is never overwritten. Other reports under this row: cluster-sizes.html (how many groups Vespera made, one page per group) and seed-corpus-comparison.html (your documents compared with your seed documents).
- **arrangementApproved:** Key: arrangementApproved. Value: either the 12-character name that arrangement.html shows on its own line under the heading "What you are being asked", or the word auto. A name approves only that one grouping. If Vespera groups your documents again (for example after you change the Relevance cut-off row or add documents), it shows a new name and waits until you paste that new name here. auto approves every grouping without waiting for you; arrangement.html is still written each time. A name that does not match the current grouping: pages are not written until you paste the current name. A very large group can be spread over several pages (see the Largest group page row). Built-in value: empty (no grouping approved, so no pages are written).
- **generationModel:** Key: generationModel. Write the model's name the way Ollama, the program that runs AI models on this computer, knows it (for example qwen3:8b). Left empty, Vespera uses the model it ships with, shown in the line under this row. If the model is not installed, Vespera downloads it once, when it starts writing; the download is several gigabytes, and if it fails the writing stops. Vespera does not use a model that sends text off this computer, such as one whose name ends in "cloud". No report helps choose it. Your approval and your saved answers are kept.
- **generationContextWindow:** Key: generationContextWindow. The number counts tokens, which are small pieces of words; Vespera counts two tokens per word. About 1,280 tokens are always kept for Vespera's instructions and for the text the model writes; the rest is for document text. So the built-in 8192 leaves about 6,900 tokens, roughly 3,450 words of document text. If you leave this empty, Vespera uses 8192. The model reads the first piece of each document's text, one document after another, starting with the documents closest to your seed documents (the documents you put in your seed folder). It skips a document whose first piece is too big to fit on its own. When the space is full, the group's remaining documents are left out, and the page says "Written from the first N of the M documents in this group." If no document fit, the page has no text from the model and says so, but still lists every document in the group. The panel will not save a value below 1282: that leaves room for only about one word of document text. Useful values are much higher. If profile.yaml is edited by hand to a value below 1282, Vespera stops with an error before any page is written. A larger number needs more spare memory on the computer that runs the writing model. If that model runs on a different computer, the report linked under this row tells you nothing about that computer's memory.
- **clusterPageByteCeiling:** clusterPageByteCeiling. Each group of similar documents has its own page in the Output folder. This value splits a group's page into several pages when the page would be larger than this many bytes. Pages break between documents, never inside one. The first page keeps the writing model's summary of the group, or the note saying no summary was written. A group with one document or none is never split. A page can still be larger than the limit when one document alone is. Left empty, every group stays on one page. Enter a whole number of bytes from 1 to 9223372036854775807; the panel refuses anything else and says why. If profile.yaml is edited by hand with a value that is not valid, Vespera ignores it. The last line in the Output panel then says so, when a run that writes the pages ends. The report shows how many groups there are and, for each group, the size its page would have on one page: the largest, the middle one (half are smaller), the size 95 of every 100 stay under, how many groups are larger than each of four sizes, and the ten largest (with how many documents each lists and how many pages were written for it). Once a limit is set, it also shows how many groups were split, how many pages were written in all, and how many pages are still over the limit. For a group that is split, its pictures are read again; no writing model is asked anything. When you raise the limit or empty it, a group's extra pages from before stay in its folder.
- **logTimestampShareFloor:** Setting: logTimestampShareFloor. The value is a share from 0 to 1: 0.7 means 70% of a file's lines. A line counts when its first 64 characters hold a time stamp: a date with a time (2024-03-01 10:15, 01/03/24 10:15), a time alone (10:15:30), the form 20240301 101530, or the form 'Mar 01 10:15:30'. A date alone, such as 2024-03-01, does not count. Only text files are checked, and only those with ten or more counted lines. Blank lines are not counted, and neither are lines that carry on the line above: indented lines, or lines of an error listing that start with 'at ', 'Caused by:' or '...'. A file over 128 KB is judged only on its first 64 KB and its last 64 KB. A file left out is not used and gets no page; your files are not deleted. Set too low, documents whose lines carry clock times, such as minutes noted by the clock or exported chat transcripts, disappear from the pages without warning. Left empty, no file is left out as a log. format-mix.html counts the text files in each 10% step (0-10%, 10-20%, and so on).
- **extractionAttempt:** Key: extractionAttempt. A whole number. Empty or 1 means the first try; to try again, write the next number (from empty or 1, write 2). Only files left unread because the program that turns files into text crashed or took too long are tried again. A file that could not be read because of the file itself (for example a damaged or locked file) is never tried again, so raising the number will not help it. Files read on the new try are used like any other document. Nothing from the earlier try is deleted, and answers you saved in relevance-labels.yaml are kept. A grouping you approved must be approved again even if the groups look the same; if the Approved grouping row says auto, there is nothing to approve. To go back, write the earlier number (empty or 1 for the first try); going back turns nothing into text again. Going back after approving the newer try's groups? When the run ends, the last lines of the Output panel name the earlier grouping. Write that name into the Approved grouping row.
- **codeNameEndings:** Key: codeNameEndings. A list of name endings, each beginning with a dot, separated by spaces, with no wildcard (for example: .java .sql). Upper and lower case count the same; where two listed endings match, the longer one counts. Applies only to plain-text files (.txt, .xml, .sql, .java and the like) and to files Vespera cannot recognise (no ending or an unfamiliar one) whose beginning and end read as text. A PDF, Word or Excel file, or an image, stays a document whatever its ending. Pages made by a documentation generator, such as Javadoc, are kept as code when the generator's name or layout is written inside the page, even if their ending is not listed. Code is not grouped, and no page text is written for it. A file that changed after Vespera listed your folders is not copied to code/. If an ending is also in "Leave out files by name ending", its files are left out, not kept as code. Left empty, no file is kept as code because of its name ending. A value that is not such a list is ignored, as if empty, and the run says so at the end.
- **outOfScopeNameEndings:** Setting: outOfScopeNameEndings. Endings of files you know are not documents, for example .ok .tmp. A file left out has no text read out of it, gets no page, and is not checked for duplicates; your files are never deleted. The ending is checked only for plain text files and files whose kind Vespera cannot recognise from their content. A PDF, Word or other recognised file is always kept, whatever its name ends with. Start each ending with a dot; separate endings with spaces or commas. Upper and lower case count the same. Do not use * ? / or \, and no ending made only of dots. One wrong entry makes Vespera ignore the whole list: nothing is left out by name until you fix it, and the last line in the Output panel names this setting. Empty: no file is left out by its name. In format-mix.html, look under "Name endings of text files and files of no known kind" for endings to list, and under "What the files turned out to be" for how many files the list left out. With Approved grouping set to auto, nothing waits for your approval. Answers you saved with Record my answers are kept when a new sample is picked. If you put an old list back, the pages made with it come back without being read or written again. Only files the new list lets back in have their text read out for the first time.
- **translationSimilarityFloor:** Setting: translationSimilarityFloor. A number from 0 to 1. Near 1, two documents in different languages must say almost exactly the same thing to count as translations. Left empty, Vespera pairs documents only by their file paths: two paths are paired when they differ only in a language folder, such as en/guide/intro.html and it/guide/intro.html. Those path pairs are always kept, whatever this number. In translations.html the rows run from the lowest value to the highest, and each row lists the pairs first found at that value. A value finds the pairs on its own row and on every row after it, so pick the lowest row where neither it nor any row after it shows a wrong pair. A pair is wrong when one of its documents already has a path pair in the other language: for example it/a.html paired with en/b.html is wrong, because by path it/a.html already pairs with en/a.html. Documents in the same language are never paired by this number. Which copy of a translated document goes into the pages is decided by Preferred languages (another row on this tab); if no copy is in a preferred language, Vespera keeps the copy whose file path comes first alphabetically; if Preferred languages is empty, every copy is kept. A change also redoes the measuring of how close each document is to your seed documents (the documents you put in your seed folder). With the Approved grouping row set to auto, nothing waits for your approval. Answers you already saved with Record my answers are kept.
- **preferredLanguages:** Key: preferredLanguages. Two-letter language codes, first choice first, separated by spaces or commas, for example: it, en. Empty: every copy is kept. If one entry is not a two-letter code, Vespera ignores the whole list and keeps every copy. If no copy is in a listed language, Vespera keeps the copy whose file path comes first alphabetically. If two or more copies are in the same language, Vespera cannot pick one and keeps them all. Copies count as the same document in two ways: by the row "When two documents are translations" on this tab, and by file paths that differ only in a language folder, such as en/guide/intro.html and it/guide/intro.html. Copies left out get no page; your files are not changed or deleted.
- **configurationSettingShareFloor:** Key: configurationSettingShareFloor. The value is a share from 0 to 1: the share of a text file's lines that are program settings, such as "port = 8080", "name: value" or "[section]". 0.8 means 80%. A file counts as configuration when at least that share of its lines are settings; a lower number makes more files count. A file that counts as configuration gets no page and none of its text is used; your files are not deleted. Empty, or not a number: no file counts as configuration. Counting: blank lines and comments (#, ;, !, //) are not counted; a file needs at least ten counted lines to count by its share; for a file over 64 KB only its first and last 64 KB are read. At 1: only files made entirely of settings lines count. Above 1: no file counts by its share. At 0 or below: every text file with ten or more counted lines counts. Once a value is set, the build and logging set-up files of Maven, logback, log4j 2, .NET and Spring always count as configuration, whatever their share. Never affected: files that describe how data or a web service is laid out (XML Schema .xsd, WSDL .wsdl, OpenAPI or Swagger, JSON Schema) stay documents, unless their name ending is listed in the Code name endings row. A configuration file inside a code folder is treated as part of that code and copied with it into code/ in the Output folder. Inside your documents folder, a code folder is the nearest folder holding a build file such as pom.xml; other code folders are listed in the Code folders outside the documents folder row. Answers you already saved with Record my answers are kept.
- **deliverableLanguage:** Setting name: deliverableLanguage. Write "en" for English or "it" for Italian. No other language is available. If you leave it empty, the pages are in English. The language applies to the pages in the Output folder, to the browsable copy in the website folder inside it, and to the Confluence pages. The reports on this tab and the progress page stay in English whatever you pick. If you left the Output folder setting blank, the new pages go to a new folder and the old ones stay where they are. If you named an Output folder, name a new, empty one before you change the language. If you keep the old folder, Vespera rewrites the text but will not save the pages there. The rewritten text is kept, so the next time you start Vespera it is used and not written again. The next time you press Publish, the Confluence pages are replaced by the ones in the new language. Old Confluence pages with no matching page in the new language go to the Confluence trash. Your files are not read again, and the documents are not grouped again.
- **clusterResolution:** Key: clusterResolution. Vespera files each relevant document under the seed document it is closest to in content (seed documents are the documents you put in your seed folder). It then splits the documents under each seed document into groups by subject. This number sets how finely that split is made. Each group gets its own page in the Output folder, or several pages if it is large. Any number above 0 works; there is no upper limit and no unit. Fractions are fine, for example 0.5 or 2.5; 1 is the usual middle value. Left empty, Vespera uses its own value, 1.0 unless your settings name another. A value that is not a number above 0 (text, 0, a negative number) is ignored: the run uses the value Vespera would use if the row were empty, and the progress page says so. The number changes only how documents are grouped; it does not decide which documents are kept or left out. Approval: to approve the new grouping, open arrangement.html from the link under the Approved grouping row and paste the new grouping's name into that row. If that row says auto, Vespera does not wait for you and writes the pages at once, so there is nothing to approve again.
- **codeSetFolders:** Key: codeSetFolders. One full folder path per entry, for example D:\code\billing. Add or remove these folders in the sidebar. Empty: no folder outside the documents folder is read. Vespera never writes into these folders. Only the code, and the build and configuration files kept with it, is copied, unchanged, to the code/ folder inside the Output folder; other files in the folder are not copied. Documents found in these folders are treated like your other documents: their text is read, they can go into the pages, and they can be picked for you to judge as relevant or not. Vespera refuses to start if a listed folder is missing. It also refuses if a listed folder overlaps (is the same as, is inside, or contains) any of: your documents folder, your seed folder, the Output folder, the working folder (where Vespera keeps its own files), or a folder listed earlier here. With the Approved grouping row set to auto, nothing waits for your approval. Answers you already saved with Record my answers are kept. Rules: ADR-334, ADR-284.
- **foldersNotWalked:** Key: foldersNotWalked. A list of folders inside your documents folder. Leave it empty and every folder is read. Vespera never opens a listed folder, so the folders inside it are skipped too. Its files are not read, not compared with other documents for the same content, and never appear in a page. This is not the same as marking a folder not relevant: Vespera still reads a not-relevant folder and marks each of its files not relevant for you in relevance-labels.yaml. After a change, only files never read before have their text read out. The change applies the next time you start Vespera from the beginning; a stopped run that you continue keeps the folder list it started with. With the Approved grouping row set to auto, nothing waits for your approval. Answers you already saved with Record my answers are kept. Code folders outside the documents folder have their own row.
- **confluenceBaseUrl:** Setting: confluenceBaseUrl. Write the site's address starting with https://, for example https://your-company.atlassian.net. You may add /wiki at the end, but nothing else after the site name. Only Confluence Cloud sites are supported. Left empty, Publish to Confluence cannot run; publishing only to the website (the HTML copy in the Output folder) does not need it. It works together with the Confluence space, the page or folder to publish under, and the sign-in email on this tab. The pages you published before are not moved or removed from the old site when you change it.
- **confluenceSpaceKey:** Key name: confluenceSpaceKey. The space's short code is in its web address, after /spaces/ (for example .../wiki/spaces/DOCS/...). If the VESPERA_CONFLUENCE_SPACE_KEY variable is set where Vespera runs, its value is used and this setting is ignored. Everything below assumes that variable is not set. Empty: Publish to Confluence refuses to start and names this setting. Publishing only the website (the HTML copy) still works. The page or folder named in the next settings (by number or by title) must be in this space. After a change, pages already in the old space stay there until you remove them yourself in Confluence. Reading, sorting and writing your documents never use this value.
- **confluenceFolderId:** Key: confluenceFolderId. Only digits: the number in the address of the Confluence page or folder, for example 123456789. The page or folder must be in the Confluence space set above. Fill in this or the title setting (confluenceFolderTitle), never both. If both or neither are filled in, Publish sends nothing and tells you to fix it. Your documents are processed the same with or without it. Publish never moves pages. After your first publish, if you point this at a different page or folder, the next Publish stops before changing anything and shows the number of the page or folder where your pages are now. To go on, put that number back, or move the page titled Vespera (and the pages under it) to the new place yourself in Confluence. Publishing only to the website copy does not use it.
- **confluenceFolderTitle:** Key: confluenceFolderTitle. Text, empty by default. Type the title exactly as Confluence shows it, in the Confluence space you have set. If no page in that space has this title, or more than one does, Publish stops and asks you to fill in the Confluence page or folder number setting (confluenceFolderId) instead. Fill in either this or the number, never both: with both filled in, or both empty, Publish sends nothing and tells you to fix it. Your pages go under one top page titled Vespera, with the others under it. Publish never moves pages: if you have already published and you point this at a different page or folder, the next Publish stops before changing anything. To go on, change this back, or in Confluence move the page titled Vespera (and the pages under it) to the new place yourself. Publishing only to the website copy does not use this setting.
- **confluenceEmail:** Key: confluenceEmail. Text, an email address such as you@example.com. Each time you publish to Confluence from the control panel, you are asked for the API token of the same Atlassian account (a password-like key you create in your Atlassian account settings). The token is never saved. Empty: publishing to Confluence from the control panel is refused until you fill it in. Publishing only to the website (the HTML copy of the same documentation) does not need it.
